# JEV 儀表板：KPI 大數字卡（設計）

日期：2026-10-07

前提：[主 spec](2026-09-23-jev-dashboard-design.md)、[比率 spec](2026-09-28-ratio-metric-design.md)、[儀表板篩選器 spec](2026-10-07-dashboard-filters-design.md)（下稱「篩選器 spec」）。本文件只寫這次改變的部分。

## 1. 問題

現有的圖型都不能用一個大數字回答「這個月營收多少、比上個月多還少」。backlog「補齊」P2：顯示本期數字、跟上期比的變化，超過門檻就變色（對標 Grafana 的 Stat／Gauge）。

## 2. 規則

### 2.1 一張 KPI 卡顯示什麼

- 一個數值（一般數字欄位或比率），在一個日期欄位上照期別（月或季）分期。
- **本期**是資料裡最後一個已經結束的期，**上期**是它前一個有資料的期。今天所在的那一期和之後的期都不算，規則跟異常檢查一樣（`HighlightSummarizer`）：今天 2026-10-07、期別是月時，本期是 2026-09，上期通常是 2026-08。
- 卡片上：
  - 大數字：本期的值。一般數字用縮寫（「1.2 億」，`Intl.NumberFormat('zh-TW', { notation: 'compact' })`），比率用百分比到小數一位（「4.3%」）。
  - 下面一行：「2026-09 · 比 2026-08 ▲ 5.2%」。比率改寫百分點：「比 2026-08 ▼ 0.8 個百分點」。上期是 0 時不算百分比，只寫「比 2026-08 增加 1,200」。
  - 只有一期已經結束時：寫「2026-09 · 沒有前一期可以比」。
  - 一期都還沒結束（例如資料只有這個月）：大數字寫「—」，下面寫「還沒有已經結束的期間」。
  - 本期是空值（比率的分母是 0）：大數字寫「—」。
- 變化的箭頭和文字一律用中性色。漲不一定是好事（退貨率漲是壞事），不靠顏色表示好壞（主 spec 3.5「好消息不染綠」）。

### 2.2 門檻

- 擁有者可以幫每張 KPI 卡設一個門檻：「低於」或「高於」某個值。沒設就不變色。
- 本期的值碰到門檻時，大數字換成警示色（`--tc-err`，跟「嚴重警示」徽章同一個顏色），下面多一行「低於門檻 100 萬」或「高於門檻 5%」。
- 門檻跟值的單位一樣。比率在畫面上輸入百分比（輸入 5 代表 5%），存成小數（0.05）。
- 門檻比的是本期的值，不是變化。

### 2.3 怎麼產生

- **分析時自動放**（第一次分析，不含「調整」）：
  - 條件：候選欄位（`ConfigAssembler.candidates`）裡有角色是 `time` 的欄位。沒有就不放 KPI 卡。
  - 數值：候選裡角色是 `measure` 的欄位和比率，先放焦點欄位，再照重要性；只取 `round(importance) ≥ 2`（重要、核心指標）或是焦點的，最多 3 個。一個都沒有就不放。
  - 日期欄位：候選裡第一個 `time` 欄位（候選已經照重要性排過）。
  - 期別：資料範圍超過 3 年用季，其他用月（`ConfigAssembler.timeGrain` 算出 `day` 時也用月）。
  - 加總方式：`sum`；比率照比率的算法（每組先加總再相除）。
  - KPI 卡排在最上面一排，每張 4 欄寬、2 列高（`x` 是 0、4、8，`y` 是 0）；其他圖從 `y = 2` 開始照原本的方式排，明細表放最後。
  - KPI 卡不算進「最多 6 張圖」，也不佔 `chart_count` 的張數。
  - 不另外問 JEV。數值和日期欄位都從第一輪已經有的答案（重要性、角色、相關性）照規則挑。
- **調整模式**：KPI 卡跟其他卡一樣問 `keep_<chartId>` 要不要留；不新增 KPI 卡。重新排版時 KPI 卡照樣排在最上面一排。
- **手動加**：已存的儀表板，擁有者可以按「加 KPI 卡」，填 2.4 的表單，加在儀表板最下面（走既有的「加到既有儀表板」，一批一張）。
- **改設定**：擁有者在已存儀表板的 KPI 卡上按「設定」，用同一個表單改，包括門檻。存檔走 `PUT /api/dashboards/{id}`。

### 2.4 KPI 表單（對話框，max-width 480）

- 標題：「加 KPI 卡」或「KPI 卡設定」。
- 欄位：
  - 來源：自己能用的來源（`GET /api/datasources`）。改設定時不能換來源。
  - 數值：這個來源的數字欄位和比率，顯示畫面上的名稱。
  - 加總方式：加總、平均、筆數。選比率時不顯示（比率固定是先加總再相除）。
  - 日期欄位：這個來源的日期欄位，預設第一個。來源沒有日期欄位時，寫「這個來源沒有日期欄位，不能做 KPI 卡」，「加入」停用。
  - 期別：月、季。
  - 標題：預設空白，空白時用數值的名稱。
  - 門檻：「不設、低於、高於」加一個數字輸入框。比率的輸入框後面有「%」。
- 按鈕「取消」「加入」（或「儲存」）。

### 2.5 跟其他功能

- **篩選器**：KPI 卡跟其他卡一樣，先篩選資料列再算。選了「上季」、期別是月時，本期是上季最後一個已經結束的月。篩選器 spec 2.2 的期間日期欄位規則：KPI 卡有 `timeGrain`，用它的 `x`。
- **異常檢查**：KPI 卡也做異常檢查。摘要的方式跟沒有系列的折線圖一樣（`HighlightSummarizer` 的 `SUMMARIZABLE_TYPES` 加上 `kpi`），徽章顯示在卡片標題列。
- **唯讀檢視、訪客**：看得到 KPI 卡和門檻顏色，沒有「設定」「加 KPI 卡」。
- **製圖頁預覽**：自動放的 KPI 卡在預覽裡就看得到，「✕」可以拿掉。

## 3. 卡片設定

```json
{
  "chartId": "c1",
  "type": "kpi",
  "title": "amount",
  "gridPos": { "x": 0, "y": 0, "w": 4, "h": 2 },
  "mapping": { "x": "order_date", "value": "amount", "aggregate": "sum", "timeGrain": "month" },
  "options": { "threshold": { "op": "below", "value": 1000000 } },
  "datasourceId": "…"
}
```

- `UniversalTransformer.TYPES` 加上 `kpi`。`problem()`：`kpi` 需要 `x`、`value`、`timeGrain`；`timeGrain` 只能是 `month`、`quarter`；`aggregate` 不能是 `none`。
- `DashboardService.cardProblem`：`options.threshold` 有給時，`op` 要是 `below` 或 `above`，`value` 要是有限的數字。訊息：「KPI 門檻的條件只能是低於或高於」「KPI 門檻要是數字」。
- 自動產生的標題（`ConfigAssembler.title`）：`kpi` 就是 `value`。這樣 `DashboardDataService.relabelled` 會照樣換成顯示名稱。

## 4. 資料

- `/data` 回傳的 KPI 卡：`dimensions` 是 `[x, value]`，`rows` 是**已經結束的期**，照時間排，每列 `[期, 值]`，最多最後 13 期（前端只用最後兩期；多留是給之後的走勢小圖）。比率的 `percent` 是 true。
- 「已經結束」要知道今天：`DashboardDataService` 照篩選器 spec 已經注入 `Clock`，轉換 KPI 卡時把今天傳進去（`UniversalTransformer` 多一個帶 `LocalDate today` 的多載，或由 `DashboardDataService` 在轉換後裁掉，擇一，測試要涵蓋）。
- 分組的算法跟有 `timeGrain` 的折線圖一樣（`grouped`），比率的期間對齊也一樣。
- 預覽（`/preview/data`）也一樣。

## 5. 後端其他改動

- `ConfigAssembler`：
  - `CHART_TYPES_ZH` 加 `kpi`：「KPI 大數字卡：顯示最近一期的數字和跟前一期比的變化」（`keepQuestion` 要用它的中文名）。KPI 不會出現在第二輪的圖型選項裡，因為 `pairTypes`、`tripleTypes` 不產生它。
  - 新增 `kpis(candidates)`：照 2.3 回傳 KPI 卡（gridPos 先留空）。`assemble` 把它們放在最前面。
  - `layOut` 先排 KPI 卡（每排 3 張，4×2），其他圖從 KPI 列下面開始，明細表放最後。
  - `adjust` 的 `MAX_CHARTS` 不算 KPI 卡。
- `HighlightSummarizer.SUMMARIZABLE_TYPES` 加 `kpi`。
- 不改資料庫。

## 6. 畫面

### 6.1 卡片

- `ChartCard` 遇到 `kpi` 不走 ECharts，畫 2.1 的內容：
  - 大數字置中偏左，字級約 32px，`font-variant-numeric: tabular-nums`。
  - 下面一行比較的文字，次要文字色、12px。
  - 碰到門檻時，大數字用 `--tc-err`，加一行「低於門檻 …」。
  - 卡片太小時大數字不換行，用 `text-truncate`，`title` 放完整數字。
- 擁有者看已存的儀表板時，KPI 卡標題列「✕」左邊多一顆「設定」（`mdi-cog-outline`，`aria-label="KPI 卡設定"`）。預覽裡沒有。
- 篩選器 spec 6.4 的「沒套用篩選」、「篩選後沒有資料」照樣適用。

### 6.2 儀表板頁

- 擁有者打開自己的儀表板時，篩選列右邊多一顆「加 KPI 卡」（`mdi-numeric`，`variant="text"`）。

## 7. 測試

### 7.1 後端

- KPI 轉換：本期、上期照「已經結束」挑（月底、月初、跨年、季）；只有一期；沒有已結束的期；比率的本期是 null；最多 13 期。
- 篩選後的 KPI（「上季」配月）。
- `problem()` 和門檻驗證的每一條訊息。
- `ConfigAssembler`：沒有時間欄位不放；重要性和焦點的挑法、最多 3 張；比率可以當 KPI；季、月的選法；`layOut` 的位置；`adjust` 保留 KPI 卡、不新增、不算進 6 張；`keepQuestion` 用 KPI 的中文名。
- 異常檢查會摘要 KPI 卡。

### 7.2 前端

- KPI 卡的四種狀態（正常、只有一期、沒有已結束的期、本期是空值），比率的百分比和百分點，上期是 0。
- 門檻：低於、高於、比率的百分比換算、沒設。
- 「設定」和「加 KPI 卡」只有擁有者看得到；表單的欄位連動（換來源、選比率時藏加總方式、沒有日期欄位）；送出的卡片設定。

### 7.3 瀏覽器（主 session 自己做）

- 用有日期欄位的上傳檔分析：最上面一排出現 KPI 卡，數字跟 `/data` 對得上，期別是上個月。
- 加一張比率的 KPI 卡，設「高於 5%」，碰到時變色。
- 改設定、存檔、重新整理後還在；檢視者看得到顏色、沒有設定鈕。
- 套用篩選後 KPI 數字跟著變。
- 自己讀每一張截圖。

## 9. 不做

- 走勢小圖（sparkline）。資料已經留了最後 13 期，之後只要前端畫。
- 跟去年同期比、本期至今比上期同期（使用者選了「最近結束的一期」）。
- 多段門檻、用變化幅度當門檻、目標值和達成率的進度條（Grafana 的 Gauge）。
- 日期期別的 KPI。
- 一般卡片的「設定」（backlog P3「編輯已存的卡片」）。

## 10. 決定（2026-10-07）

| 題目 | 選擇 | 沒選的 |
|---|---|---|
| 本期 | 最近結束的一期，跟前一期比（使用者選） | 本期至今比上期同期、本期至今比上一整期 |
| 怎麼產生 | 分析自動放，也能手動加、設門檻（使用者選） | 只能手動加、只在分析時產生 |
| 門檻 | 擁有者設一個「低於／高於」的值，碰到就用警示色（使用者選） | 用變化幅度上色 |
| 漲跌的顏色 | 中性色 | 漲綠跌紅（漲不一定是好事） |
| 自動挑數值 | 照第一輪的重要性和焦點，不多問 JEV | 多問一題「適不適合當 KPI」 |
| 期別 | 月或季 | 也允許日 |
