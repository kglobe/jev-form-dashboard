# JEV 儀表板：上傳時寬表轉長表（設計）

日期：2026-10-08
前提：上傳來源見 `2026-09-23-jev-dashboard-design.md`，更新資料見 `2026-10-02-datasource-reload-design.md`。本文件只寫這次改變的部分。

## 1. 問題

公司內部的 Excel 很常把月份排成欄位：「部門、1月、2月…12月、全年合計」。上傳後每個月份都是一個數字欄位，系統找不到日期欄位，就畫不出按月趨勢，期間篩選和 KPI 卡也用不了。這次在上傳時加一個選項，把這些月份欄位轉成「月份」「數值」兩欄：原本一列 12 個月，變成 12 列，每列一個月。

## 2. 規則

### 2.1 哪些欄位會轉

勾了「寬表轉長表」之後，後端看每個欄位的標題，認得出是某個月或某一季的欄位就轉。比對前先拿掉所有空白，英文不分大小寫。

| 種類 | 認得的寫法 | 要不要另外填年份 |
|---|---|---|
| 年＋月 | `2024-01`、`2024/1`、`2024.01`、`2024年1月`、`113年1月`、`113/01`、`202401` | 不用 |
| 完整日期 | `2024-01-01`、`2024/1/1`，以及設成日期格式的 Excel 儲存格（顯示成「2024年1月」的那種），只取年和月 | 不用 |
| 只有月 | `1月`～`12月`、`01月`、`1月份`、`一月`～`十二月`、`Jan`～`Dec`、`January`～`December` | 要 |
| 年＋季 | `2024Q1`、`2024-Q1`、`2024年Q1`、`2024年第1季`、`113年第一季` | 不用 |
| 只有季 | `Q1`～`Q4`、`1Q`～`4Q`、`第1季`～`第4季`、`第一季`～`第四季` | 要 |

年份 2～3 碼的當作民國年，跟日期欄位的規則一樣。只寫數字的標題（`1`、`2`…）不認，這種標題可能是任何東西。

### 2.2 年份

- 標題沒寫年份時，用對話框填的年份，預設今年。標題自己有年份的欄位，不看這一格。
- 年份可以填西元或民國（`2026` 或 `115`），2～3 碼加 1911，結果要在 1900～2099 之間。
- 需要年份卻沒填，或填的不對，就擋下（訊息見 2.5）。

### 2.3 合計欄

標題含「合計」「總計」「小計」「累計」「全年」或「total」的欄位，轉換時不匯入。這類欄位不是月份，不會被轉；留著的話，它的值會重複出現在每一列，轉成 12 列之後加總會變 12 倍。拿掉的欄位會寫在轉換完的訊息裡。沒勾「寬表轉長表」時，這些欄位照常匯入。

### 2.4 轉出來的兩欄

- **期間欄**：值是那一期第一天的日期，例如 `2026-01-01`（1 月）、`2026-04-01`（第 2 季），所以會被判斷成日期欄位，可以按月、按季分組。名稱沒填時，月份叫「月份」，季叫「季」。
- **數值欄**：原本那一格的值，型別照一般上傳的規則推斷。名稱沒填時叫「數值」。
- 其他沒被轉、也沒被拿掉的欄位照原樣留著，每一列都帶。欄位順序是：留下的欄位照原本順序，再接期間欄、數值欄。
- 空白的格子不產生資料列。年度表裡還沒到的月份是空白，不會變成值是 0 或空白的一期。
- 資料列順序：照原本的列，每一列裡照欄位由左到右。
- 筆數上限算轉換後的筆數；全部都是空白、轉完一列都沒有，跟一般上傳一樣回「沒有資料列」。

### 2.5 擋下的情況

都回 400，什麼都不存：

- 一個月份或季的欄位都找不到：「找不到標題是月份或季的欄位，例如 1月、2024-01、Q1」。
- 月份和季的欄位混在一起：「月份和季的欄位不能混在一起：1月、Q1」，各舉第一個。
- 兩個欄位是同一期：「欄位「1月」和「2026-01」是同一個期間」。
- 需要年份卻沒填：「欄位「1月」沒寫年份，請填年份」；年份不對：「年份要填西元 1900～2099 年，或民國年」。
- 期間欄、數值欄的名稱一樣，或跟留下的欄位同名：「欄位名稱「部門」跟其他欄位重複，請換一個」。

### 2.6 更新資料

- 轉換方式跟著來源存下來：轉了哪些欄位、拿掉哪些欄位、兩欄的名稱、用的年份。
- 之後按「更新資料」，新檔案要跟第一次上傳的檔案是同一組欄位（留下的、轉的、拿掉的都算），順序可以不同；不一樣時照更新資料的規則列出少了、多了哪些，列的是寬表的欄位名稱。
- 欄位對了就照同樣的方式轉，用同一個年份，再照更新資料原本的規則檢查型別、寫入。整份覆蓋和接在後面都可以。每月補一個月的年度表，用整份覆蓋更新就好。
- 明年的檔案年份不同，請上傳成新的來源。

## 3. API

`POST /api/datasources/upload` 多四個選填的參數：

| 參數 | 說明 |
|---|---|
| `unpivot` | `true` 時做寬表轉長表；沒帶或其他值照舊 |
| `year` | 年份，西元或民國，見 2.2 |
| `periodName` | 期間欄名稱，空白用預設 |
| `valueName` | 數值欄名稱，空白用預設 |

回傳的來源多一個 `unpivot`（沒轉過的來源不輸出）：

```json
{ "columns": ["1月", "2月"], "dropped": ["全年合計"], "periodName": "月份", "valueName": "數值", "year": 2026 }
```

`year` 是換算成西元的年份；所有轉換的欄位都自己有年份時是 `null`。分享給別人時照樣給，裡面只有欄位名稱。

`POST /api/datasources/{id}/rows`（更新資料）不加參數，照存下來的 `unpivot` 轉。

## 4. 後端

- 新增 `Unpivot`（record）：`detect` 從標題、名稱、年份組出轉換方式，2.5 的檢查都在這裡；`apply` 把解析好的檔案轉成長表；`wideColumns` 從長表的欄位推回寬表該有的欄位，給更新資料比對。
- `DatasourceService.upload`：解析後，有勾就先 `detect`、`apply`，再照原本的流程推斷型別、檢查筆數、寫入，`unpivot` 跟著來源一起存。
- `DatasourceService.reload`：來源有 `unpivot` 時，先拿新檔案的標題比對 `wideColumns`，再 `apply`，後面照舊。
- Flyway `V8__datasource_unpivot.sql`：`datasource` 加 `unpivot_json jsonb`，舊的來源是 null，不用搬資料。
- `Datasource` 多一個 `unpivot` 欄位，`DatasourceRepository` 讀寫 `unpivot_json`。

## 5. 畫面

- 新增來源 →「上傳檔案」分頁多一個勾選框「把 1月、2月…這類欄位轉成兩欄（寬表轉長表）」。勾了才出現三格：年份（預設今年，提示「標題沒寫年份時用，例如 1月、Q1」）、期間欄名稱（提示「預設：月份，季是「季」」）、數值欄名稱（提示「預設：數值」）。
- 上傳成功後，資料頁上方的提示寫：「已把 1月～12月 共 12 欄轉成「月份」「數值」兩欄，共 36 筆；沒有匯入：全年合計」。轉的欄位超過 3 個時寫頭尾和欄數，3 個以內全部列出；沒拿掉欄位就不寫後半句。
- 更新資料的對話框，來源有轉過時說明改成：「上傳時把 1月～12月 轉成「月份」「數值」兩欄。新檔案的欄位要跟第一次上傳的一樣，會照同樣方式轉。」

## 6. 測試

後端：

- `Unpivot`：2.1 表格裡每種寫法都認得、算出對的日期；只寫數字的標題不認；民國年；年份換算和範圍；合計欄只在轉換時拿掉；2.5 每種錯誤的訊息；空白格不產生資料列；欄位和資料列的順序；名稱的預設值。
- service（記憶體裡的 repository）：上傳時轉換，存下 `unpivot`、筆數是轉換後的；期間欄是日期、數值欄是數字；沒勾照舊；轉完超過筆數上限、全部空白都擋下。更新資料：整份覆蓋、接在後面都照同樣方式轉、用同一個年份；新檔案少了月份欄或合計欄時列出寬表的差異；沒轉過的來源照舊。
- repository（PostgreSQL）：`unpivot_json` 寫進去讀得回來，沒轉過的是 null。
- controller：四個參數會傳到 service，回傳裡有 `unpivot`。

前端：

- 沒勾時表單不帶新參數，三格不出現；勾了會帶 `unpivot`、`year`、`periodName`、`valueName`。
- 上傳成功的提示文字（超過 3 欄、3 欄以內、有沒有拿掉的欄位）。
- 更新資料對話框，轉過的來源顯示轉換說明。

瀏覽器（自己用 Chrome 操作）：

1. 上傳「部門、1月～12月、全年合計」的 Excel，只填到 9 月，勾轉換：提示寫對，欄位表是部門、月份（日期）、數值（數字），沒有全年合計。
2. 拿它分析：有按月的折線圖，1 月到 9 月照順序；KPI 卡顯示最近一個已結束的月份。
3. 補上 10 月再整份覆蓋：筆數變多，圖上多一個月。
4. 用少了一個月的檔案更新：對話框列出少了哪一欄。
5. 標題是 `2025-01`… 的 CSV，年份格留空也能轉。

## 7. 決定（2026-10-08）

| 題目 | 選擇 | 沒選的 |
|---|---|---|
| 入口 | 上傳時勾選，自動找出月份、季的欄位 | 上傳後在來源頁自己勾要轉哪些欄 |
| 沒寫年份的標題 | 對話框填年份（預設今年），轉成日期 | 保留成文字「1月」，另外改排序 |
| 合計欄 | 轉換時不匯入，訊息寫出來 | 保留並提醒；擋下請使用者先刪 |
| 更新資料 | 記住轉換方式，新檔案照同樣方式轉 | 轉過的來源不能更新資料 |
| 空白格 | 不產生資料列 | 產生值是空白的一列 |
| 兩欄名稱 | 可以填，不填用「月份」或「季」、「數值」 | 一定要填 |
| migration | V8 加 `unpivot_json` | — |

## 8. 不做

- 轉「北區、中區、南區」這類不是期間的欄位。
- 以年為欄位（`2023`、`2024`）的表、按日排的表。
- 從檔案裡的「年度」欄取年份；一份檔案有好幾個年度疊在一起，要分開上傳。
- 合計列（最後一列寫「合計」）：一般上傳也一樣沒處理。
- 標題列不在第 1 列的檔案（上面有表頭標題的 Excel）：一般上傳也一樣不支援。
- 更新資料時換年份。
