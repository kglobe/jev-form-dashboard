# JEV 儀表板：依需求分析與對話式調整（設計）

日期：2026-09-25
前提：主設計見 `docs/superpowers/specs/2026-09-23-jev-dashboard-design.md`，分析方法見 `docs/JEV智慧化產製儀表板的流程與方法.md`。本文件只寫這次新增和改變的部分。

## 1. 目的

目前按「分析」之後，欄位評估和選圖全部交給 JEV 判斷，使用者沒辦法說自己想看什麼。這次加兩件事：

1. **分析前輸入需求**：使用者先寫一句「想看各區每月營收」，跟這句話相關的圖一定會出現，排在最前面，後面再補一般性的圖。
2. **預覽中對話式調整**：看到預覽後，使用者可以再說「不要圓餅圖，加各產品的數量」，系統會在目前的圖上調整，保留、移除、新增都照他的話做。也可以直接按卡片上的「✕」移除。

## 2. 範圍

做：

- 左側面板的需求輸入框。
- 預覽畫面的需求紀錄、調整輸入框和「調整」按鈕、卡片「✕ 移除」、「符合需求」標籤。
- 需求紀錄跟著儀表板存檔，打開時顯示。
- 後端：分析 API 接收需求和目前的圖、JEV 題目、組裝規則、驗證。
- 上述互動的動態效果，以及「✕」移除後的「復原」提示（第 10 節）。
- 順手修掉兩個現有問題：打開或切換儀表板時卡片會飛過畫面；設定一換，所有卡片都會重新載入（第 10 節）。

不做：

- 已存儀表板的對話式修改。之後另立 spec，可以沿用這次的調整機制。
- 用對話調整明細表的欄位。
- 讓 JEV 回答自由文字。JEV 在這個專案裡只回答結構化題目（`score`、`choice`、`noul`），這次也一樣。
- 整體外觀改成 Tactile Clean，以及載入骨架、按鈕按壓、拖拉時抬起卡片、對話框開關、圖表動畫調校、打開儀表板時卡片分批進場等通用動畫。之後另立 spec。

## 3. 畫面與流程

### 3.1 左側面板

- 「分析」按鈕上方加一個多行文字框：
  - 標籤：「想看什麼？（選填）」
  - 提示文字：「例如：各區每月營收、哪個產品退貨最多」
  - 下方說明：「這段文字會送給 JEV 做分析」
  - 最多 200 字，顯示字數計數。
- 沒填時，分析結果和現在完全一樣。
- 按「分析」時，有填就把這句話當成需求紀錄的第一句送出。

### 3.2 預覽畫面

- 上方顯示「需求紀錄」，依序列出說過的每一句話；沒有紀錄時不顯示。
- 下面一個輸入框：
  - 標籤：「想怎麼調整？」
  - 提示文字：「例如：不要圓餅圖、加各產品的數量」
  - 最多 200 字。
- 「調整」按鈕：輸入框是空的或正在處理時不能按。按下後把「目前的圖」和「需求紀錄加上這一句」送去分析，拿到新結果就取代預覽。
  - 等待 JEV 回應時：圖表區變淡（不透明度 0.6）並標示 `aria-busy="true"`，「✕」停用，「調整」按鈕顯示處理中。
  - 成功後，這句話加進需求紀錄，輸入框清空。
  - 失敗時，預覽維持原樣，在預覽畫面顯示錯誤訊息。
- 儀表板名稱：使用者改過名稱就保留他改的；沒改過就用新結果的預設名稱。
- 每張圖表卡片右上角有「✕」按鈕，無障礙名稱是「移除這張圖」。按下只在前端移除，不呼叫 API；剩下的卡片照 6.6 的規則重新排版，下次調整也不會再帶上這張。明細表沒有「✕」。
- 移除後，畫面下方中央出現提示「已移除「{title}」」和「復原」按鈕（`role="status"`）：
  - 按「復原」：這張圖放回移除前的位置（照移除前的順序，依 6.6 重新排版），提示關閉。
  - 提示停留 6 秒後自動關閉；滑鼠移到提示上或鍵盤焦點在提示裡時暫停計時。
  - 一次只有一個提示：再移除另一張圖時，新的提示取代舊的，前一張就不能再復原。
  - 按「調整」或關閉預覽時，提示立即關閉，已移除的圖不能再復原。
- `options.focus` 是 `true` 的卡片顯示「符合需求」標籤。
- 有需求紀錄、但沒有任何一張圖是 `options.focus` 時，預覽上方提示：「找不到跟需求直接相關的欄位，先顯示一般的分析結果。」
- 需求紀錄已有 10 句時，輸入框停用，並提示「需求紀錄最多 10 句」。

### 3.3 已存的儀表板

- 設定裡有需求紀錄時，圖表上方顯示一行小字：「依據：」加上每一句，中間用「 → 」連起來，例如「依據：各區每月營收 → 不要圓餅圖 → 加各產品的數量」。
- 「符合需求」標籤在已存的儀表板上照樣顯示。

## 4. API

`POST /api/jev/analyze`，body：

```json
{
  "datasourceId": "…",
  "intents": ["各區每月營收", "不要圓餅圖，加各產品的數量"],
  "current": [ /* ChartSpec[]：目前預覽裡的圖表，含明細表 */ ]
}
```

- `intents`：選填。需求紀錄，最後一句是這次的需求。每句先去掉頭尾空白，空白的句子直接丟掉。
- `current`：選填。有值就是**調整模式**，沒有就是**第一次分析**。
- 回傳：`DashboardConfig`（沒有 `id`），`intents` 等於清理後的需求紀錄，`layout` 是新的圖表。

驗證失敗一律回 400 `{"error": …}`：

| 情況 | 訊息 |
|---|---|
| 某一句超過 200 字 | 想看什麼最多 200 字 |
| 超過 10 句 | 需求紀錄最多 10 句 |
| 有 `current` 但沒有任何需求 | 請輸入想怎麼調整 |
| `current` 的卡片不合法 | 沿用現有的卡片驗證訊息 |

`datasourceId` 的擁有者檢查不變：別人的資料源回 404。

## 5. 送給 JEV 的內容

以下只在有需求時才加。沒有需求時，題目和 `state` 跟現在完全一樣。

### 5.1 `state`

在現有的 `rowCount`、`fields` 之外加上：

- `intent`：最新這句需求。
- `history`：之前說過的句子，從舊到新；只有一句時省略這個欄位。
- `current`：只在調整模式出現。每張圖列 `chartId`、`title`、`type` 和 `fields`（mapping 用到的欄位名稱），明細表不列。

敏感欄位的規則不變，只送名稱和型別；`current` 裡也只有欄位名稱，沒有任何資料值。

### 5.2 第一輪

- `imp_i`、`role_i` 不變。
- `chart_count`：第一次分析照舊；調整模式不問，因為調整不補一般性的圖。
- `rel_i`（新增，每個欄位一題，`score`）：
  - 題目：「使用者想看：「{最新需求}」。欄位「{欄位名}」跟這個需求有多相關？」
  - 選項：`["無關", "間接相關", "直接相關"]`
- `keep_<chartId>`（新增，只在調整模式，每張目前的圖一題，`choice`）：
  - 題目：「使用者最新的要求：「{最新需求}」。目前有一張圖「{title}」（{圖型中文名}，欄位：{欄位名，用、分隔}），這張圖要保留還是移除？」
  - 選項：`{"keep": "保留這張圖", "drop": "移除這張圖"}`

### 5.3 第二輪

- 每題說明的最後加上一句：「使用者想看：「{最新需求}」。」
- 第一次分析：組合照 6.3 的排序。
- 調整模式：只問含焦點欄位的組合。如果某個組合的欄位集合跟一張保留的圖相同，就把那張圖的圖型從選項裡拿掉；選項只剩 `none` 時，這個組合不問。

## 6. 組裝規則（`ConfigAssembler`）

### 6.1 焦點欄位

`rel_i` 的 `round(score)` 等於 2（直接相關），而且 confidence ≥ 0.5 的欄位。

### 6.2 候選欄位

1. 角色不是 `ignore` 的焦點欄位，依重要性由高到低排在最前面。
2. 其他欄位照現有規則補上：角色不是 `ignore`、重要性 `round(score) >= 1`，依重要性排序。
3. 總數上限維持 8 個。焦點欄位超過 8 個時，取重要性最高的 8 個。

### 6.3 組合排序

排序依序比三件事：有沒有焦點欄位（有的排前面）、組合分數（平均重要性，高的排前面）、產生順序。

- 第一次分析：取前 2K 組。
- 調整模式：只留含焦點欄位的組合，取前 2 ×（6 − 保留張數）組。

### 6.4 第一次分析的組裝

1. 照現有規則丟掉答 `none` 或 confidence 低於 0.5 的組合，剩下的依 6.3 的順序取前 K 張。
2. **保證至少一張焦點圖**：有焦點組合、但取出的圖裡沒有一張含焦點欄位時，把排序最前面的焦點組合，用它第一個合法圖型放在第一張。如果原本已經取滿 K 張，就拿掉最後一張，維持 K 張。
3. 含焦點欄位的圖，`options.focus` 設成 `true`。

### 6.5 調整模式的組裝

1. **保留**：`keep_<chartId>` 答 `drop` 而且 confidence ≥ 0.5 才移除，其他情況一律保留。拿不準的時候寧可留著，不亂刪使用者的圖。保留的圖設定原封不動，`chartId` 和 `options` 都不變。
2. **新增**：第二輪接受的焦點組合依 6.3 的順序加在保留的圖後面，總數最多 6 張，也就是最多新增「6 − 保留張數」張。新增的圖 `options.focus` 設成 `true`。
3. **保證**：有焦點組合、這次一張都沒新增、保留的圖也沒有任何一張用到焦點欄位，而且還有空位時，照 6.4 第 2 點補上一張。
4. **不補一般性的圖**。

### 6.6 版面與編號

- 圖表依順序重新排版：每列兩張（`w: 6, h: 4`），明細表放最後（`w: 12, h: 5`）。
- 保留的圖沿用原本的 `chartId`。新圖的編號跟現有規則一樣是 `c` 加數字，數字取比目前所有 `chartId`（含明細表）的數字都大的值，依序往後接，保證不重複。

### 6.7 明細表

- 第一次分析：欄位是候選欄位，焦點欄位排前面。
- 調整模式：沿用 `current` 裡明細表原本的欄位。

## 7. 資料與儲存

- `DashboardConfig` 加一個選填的 `intents`（字串陣列）。JSON 省略空值，跟著整包設定存進 `config_json`，資料表不用改。
- 存檔和預覽時的驗證加上 `intents`：最多 10 句、每句最多 200 字、不能是空白。
- 舊儀表板沒有 `intents`，照常可以打開，也不顯示「依據」。
- `options.focus` 存在 `ChartSpec.options` 裡，資料表同樣不用改。

## 8. 錯誤處理

- 第一次分析失敗：錯誤顯示在左側面板，訊息沿用現有的（例如 503「未設定 TYPESAFE_API_KEY」、502「JEV 呼叫失敗（HTTP n）」）。
- 調整失敗：預覽維持原樣，錯誤顯示在預覽畫面。
- JEV 沒回某一題 `keep_<chartId>`：當作保留。
- JEV 沒回某一題 `rel_i`：這個欄位不算焦點欄位。

## 9. 隱私

多送給 JEV 的只有兩樣：使用者寫的句子，以及目前圖表的標題、圖型、欄位名稱。沒有任何資料值或樣本，敏感欄位的規則不變。輸入框下方會提示這段文字會送給 JEV。

## 10. 動態效果

原則：只在狀態真的改變時才動，介面動畫都在 200ms 以內。只動 `transform` 和 `opacity`，不動 `margin`、`padding`、`height` 這類會讓版面重排的屬性。

### 10.1 共用設定

- 放在儀表板模組裡的 `motion.css`（模組不能依賴模組以外的檔案）：

  ```css
  :root {
    --tc-ease-out: cubic-bezier(0.23, 1, 0.32, 1);
    --tc-dur-1: 120ms; /* 退場、淡出 */
    --tc-dur-2: 160ms; /* 提示、需求紀錄、等待狀態 */
    --tc-dur-3: 200ms; /* 卡片進場 */
  }
  ```

- JS 要判斷使用者是否開啟「減少動態效果」時，用模組裡 `motion.js` 匯出的 `prefersReducedMotion()`，它讀取 `matchMedia('(prefers-reduced-motion: reduce)')`。

### 10.2 修正：打開或切換儀表板時卡片飛移

- 現況：grid-layout-plus 對卡片位置預設有 `transform .2s ease` 的轉場。每份儀表板的 chartId 都是 `c1`～`c6`，元件會被重用，所以從 A 切到 B 時，卡片會從 A 的位置滑到 B 的位置；第一次打開時，卡片也會從左邊滑進自己的欄位。
- 修法：
  - `App.vue` 裡顯示已存儀表板的 `DashboardView` 加上 `:key="current.id"`，換一份儀表板就整個重建。預覽裡的 `DashboardView` 不加 key，調整時保留的卡片才能滑到新位置。
  - `DashboardView` 等 `GridLayout` 觸發 `layout-ready` 後，在下一幀才替外層加上 `is-settled`。沒有 `is-settled` 時，位置轉場一律關掉：

    ```css
    .vgl-layout:not(.is-settled),
    .vgl-layout:not(.is-settled) .vgl-item { transition: none !important; }
    ```

- 結果：打開和切換時，卡片直接出現在自己的位置；之後的拖拉和補位，沿用套件的 200ms 位移轉場。

### 10.3 修正：設定一換，保留的卡片不重新載入

`load()` 現在一開始就清空所有卡片的資料，設定一換，每張卡片都會閃回「載入中」、圖表重畫。改成只清掉不在新版面裡的 chartId；還在的卡片保留原本的資料，等新資料回來再更新，卡片元件也不重新掛載。

### 10.4 新增卡片的進場

- 對象：調整後新增的卡片，以及按「復原」放回來的卡片。第一次打開儀表板或預覽時不做進場動畫（見第 2 節「不做」）。
- 效果：淡入加位移，`opacity` 從 0 到 1、`translateY(6px)` 到 0，時長 `--tc-dur-3`（200ms），easing `--tc-ease-out`。同時有好幾張時，依版面順序每張錯開 30ms，第 6 張以後不再往後延（最多延遲 150ms）。
- 動的是 `GridItem` 裡面的卡片。`GridItem` 自己的 `transform` 是格子位置，不能拿來做動畫。

### 10.5 「✕」移除

- 按下後，該卡片先退場：`opacity` 從 1 到 0、`scale(1)` 到 `scale(0.98)`，時長 `--tc-dur-1`（120ms）。退場結束才套用新版面，其他卡片用套件的 200ms 位移轉場補位。
- 「✕」按鈕靜止時就看得到（`--tc-muted` 色，不是 hover 才出現）；hover 時變成主文字色，按下時 `translateY(1px)`；點擊範圍至少 24×24。grid-layout-plus 預設不會把按鈕上的點擊當成拖拉。
- 退場那 120ms 不能中斷，補位可以中斷。

### 10.6 「調整」

- 等待中：圖表區的 `opacity` 在 `--tc-dur-2`（160ms）內降到 0.6，並標示 `aria-busy="true"`；「✕」停用；「調整」按鈕顯示處理中。
- 結果回來後，依 chartId 比對新舊版面：
  1. 被移除的：照 10.5 退場（120ms）。
  2. 保留的：不重新進場，也不閃「載入中」；位置有變就用 200ms 滑到新格子。
  3. 新增的：照 10.4 進場。它們排在保留的卡片後面，大約在補位完成時到位。「符合需求」標籤跟著卡片一起出現，不另外做動畫。
- 整段大約 320–470ms。
- 等待中可以按「取消」直接關掉預覽。

### 10.7 「復原」提示

- 出現：`opacity` 從 0 到 1、`translateY(6px)` 到 0，時長 `--tc-dur-2`（160ms），ease-out。關閉：方向相反，時長 `--tc-dur-1`（120ms）。
- 按「復原」後，那張卡片照 10.4 進場回到原位，其他卡片用 200ms 補位。

### 10.8 需求紀錄新增一句

新的一句從 `opacity` 0、`translateY(4px)` 淡入到定位，時長 `--tc-dur-2`（160ms），easing `--tc-ease-out`。

### 10.9 減少動態效果

使用者在系統開啟「減少動態效果」（`prefers-reduced-motion: reduce`）時，以上所有效果都瞬間完成：JS 不等退場的 120ms，錯開的延遲也歸零。CSS 用 `motion.css` 裡的 `@media (prefers-reduced-motion: reduce)` 關掉這些轉場，JS 用 `prefersReducedMotion()` 判斷。

## 11. 測試

- **後端**
  - `ConfigAssembler`：焦點欄位一定進候選並排前面、組合排序、第一次分析保證至少一張焦點圖、調整模式的保留與移除（包含信心不足時保留）、跳過跟保留的圖重複的圖型、不補一般性的圖、上限 6 張、`chartId` 接續、明細表欄位。
  - 沒有需求時的結果跟現在完全一樣：現有測試全部照舊通過。
  - `AnalyzeService`：只有在有需求時才出現 `rel_i` 和 `state.intent`；調整模式才出現 `keep_<chartId>` 和 `state.current`，而且不問 `chart_count`；第二輪說明帶上需求；敏感欄位的樣本仍然不會送出（沿用「機密備註」的檢查）。
  - `JevController`：每條驗證的 400 訊息、別人的資料源回 404、回傳的 `intents` 是清理後的結果。
  - 儀表板存檔：`intents` 能存能讀，驗證會擋下不合規的內容。
- **前端**
  - 輸入框、字數計數、說明文字；分析時送出 `intents`。
  - 預覽的需求紀錄、調整輸入框、「調整」按鈕（空白和處理中不能按、成功後清空並加進紀錄、失敗時保留預覽）。
