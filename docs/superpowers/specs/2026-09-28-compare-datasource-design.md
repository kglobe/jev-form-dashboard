# JEV 儀表板：對照來源（設計）

日期：2026-09-28
前提：合併來源的疊加和查表見 `docs/superpowers/specs/2026-09-27-merged-datasource-design.md`（B1），每張圖各自一個來源見 `docs/superpowers/specs/2026-09-27-multi-source-dashboard-design.md`（A）。本文件只寫這次新增和改變的部分。

## 1. 目的

高階主管常要在同一張圖上比兩個來源的數字，例如每月銷售額對退貨額、各區預算對實際。

B1 的疊加會把同名的數值欄位併成一欄，接著轉換器一加總，銷售和退貨就混在一起了。對照是疊加的一種：日期和分類欄位照樣合併，數值欄位依來源分開放（`銷售·amount`、`退貨·amount`）。折線圖和長條圖要能一次畫兩個數值，JEV 分析時也要會挑這種組合。

## 2. 範圍

做：

- 疊加定義多一個 `compare: true`，強制數值欄位依來源分開。
- 長條圖、折線圖可以放兩個數值；差距大時改用左右兩條 Y 軸。
- JEV 分析對照來源時，多出「兩個數值」的組合，而且排在前面。
- 兩個數值的圖，自動標題、顯示名稱和異常檢查都要處理。
- 計數聚合改成只算非空值（B1 第 12 節）。
- 合併表單的「方式」多一個「對照」；「來源」選單順便擋掉第 6 個（backlog P3）。

不做：

- B3 的計算指標（比率），另寫 spec。
- 三個以上的數值放同一張圖；圓餅、堆疊長條、熱力、雷達圖的兩個數值版本。
- 手動編圖。製圖頁的圖還是全由 JEV 挑。

## 3. 使用情境

| 情境 | 輸入 | 對照後的欄位 | 圖 |
|---|---|---|---|
| 每月銷售對退貨 | 銷售（`order_date`、`region`、`amount`）、退貨（`return_date`、`region`、`amount`） | `date`、`region`、`銷售·amount`、`退貨·amount`、`來源` | 折線圖：每月兩條線 |
| 各區銷售對退貨 | 同上 | 同上 | 長條圖：每區兩根柱子 |
| 預算對實際 | 預算、實際（欄位相同） | `month`、`dept`、`預算·金額`、`實際·金額`、`來源` | 長條圖：每個部門兩根柱子 |

退貨金額通常只有銷售的幾十分之一，擠在同一條 Y 軸上，退貨那條線會貼在底部，所以差距大時要改成兩條 Y 軸（6.2）。

## 4. 資料模型

### 4.1 對照定義

沿用疊加的定義，多一個 `compare`：

```json
{
  "op": "union",
  "compare": true,
  "inputs": ["<銷售 id>", "<退貨 id>"],
  "columns": [
    { "name": "date", "from": { "<銷售 id>": "order_date", "<退貨 id>": "return_date" } },
    { "name": "region", "from": { "<銷售 id>": "region", "<退貨 id>": "region" } },
    { "name": "銷售·amount", "from": { "<銷售 id>": "amount" } },
    { "name": "退貨·amount", "from": { "<退貨 id>": "amount" } }
  ],
  "sourceColumn": "來源"
}
```

- `compare` 沒寫或是 `false` 就是一般疊加。B1 存下來的定義都沒有這個欄位，所以不用 migration，`merge_json` 本來就是 jsonb。
- 合併、筆數上限、巢狀層數、顯示名稱、敏感欄位全部照疊加的規則（B1 第 5、6 節），都不用改。
- `inputs` 跟疊加一樣是 2～5 個。一張圖最多兩個數值，3 個以上的來源由 JEV 兩兩配對。

### 4.2 對照組

「對照組」是兩個可以放在同一張圖上比的數值欄位，條件是：

1. 兩欄都是這個對照來源的輸出欄位，而且 schema 型別都是 `number`。
2. 兩欄的 `from` 各自只有一個來源，而且不是同一個來源。

對照模式下，5.1 的驗證已經保證每個數字欄位只來自一個來源，所以對照組就是「來自不同來源的兩個數字欄位」。對照組由 `MergeEngine` 的純函式從定義和 schema 算出來，不存進資料庫。

每個對照組同時記下可以拿來當 x 軸的欄位：兩個數值的來源都有提供的輸出欄位。只有一個來源有的欄位（例如只有退貨有的 `reason`）當 x 軸時，另一個數值每一組都是空的，整張圖只剩一邊。

## 5. 規則

### 5.1 驗證

`compare` 是 `true` 時，除了疊加原有的驗證（B1 第 9 節），還要：

- 型別是數字的輸出欄位，`from` 只能列一個來源：「對照時，數字欄位『amount』只能對應一個來源」。
- 至少有兩個不同來源各提供一個數字欄位，否則沒有東西可以比：「對照至少要有兩個來源各提供一個數字欄位」。

### 5.2 預覽提示

疊加會對「只有部分來源有」的欄位出提示。對照模式下，數字欄位本來就只來自一個來源，不出這類提示；日期和文字欄位照舊。

### 5.3 轉換器：兩個數值

- 長條圖和折線圖可以用 `measures`（剛好 2 個欄位）取代 `value`：`{ x, measures: [a, b], aggregate, timeGrain }`。
- 輸出的 dimensions 是 `[x, a, b]`，每一列是 `[x 的值, a 的聚合, b 的聚合]`。
- 分組跟單一數值一樣：`x` 是空值的列跳過，有 `timeGrain` 就先分期。
- 每個數值各自聚合：`sum`、`avg` 只看數字，`count` 算非空值。
- 某一組完全沒有 `a` 的值時，`a` 是 `null`，畫面上就是空白（折線斷開、長條不畫），不補 0。兩個數值都沒有值的組不輸出。
- 排序：有 `timeGrain` 照期別排；沒有就照 `a` 由大到小，`a` 是 `null` 的排最後。
- `aggregate` 不能是 `none`：對照來源每一列只有一邊的數值，逐列投影出來全是空的。

### 5.4 計數只算非空值

- 單一數值的圖：有 `value` 時，`count` 只算 `value` 不是空值的列；沒有 `value` 時照舊算列數。
- 雷達圖：每個指標的 `count` 只算那個指標不是空值的列。
- 所有來源都適用，不限對照來源。JEV 產生的圖一律用 `sum`，所以只有手動組的 `count` 卡片會看到差別。

### 5.5 JEV 組合

只有對照來源會多出組合。一般上傳、外部 API、疊加、查表來源的題目和結果都跟現在一樣。

- `JevController` 從定義算出對照組和來源欄名稱，交給 `AnalyzeService`。
- 來源欄（例如「來源」）的角色一律當成 `ignore`，不進候選欄位，也不進明細表。來源欄有幾個值就是有幾個輸入來源，而且每個數值欄位只會對上其中一個值，拿來畫只會得到「銷售·amount 依 來源」這種只有一根柱子的圖。
- 新組合：候選欄位裡，每一個對照組（兩欄的角色都要是 `measure`）配上：
  - 一個 `time` 欄位：折線圖、長條圖。
  - 一個 `dimension` 欄位：長條圖。
  - 時間和分類欄位都要在這個對照組可以當 x 軸的欄位裡（4.2）。
- 對應：`{ x: 時間或分類, measures: [a, b], aggregate: "sum", timeGrain: 照現有規則 }`。`a`、`b` 照候選欄位的順序。
- 排序：先比有沒有焦點欄位，再讓對照組合排在其他組合前面，最後比平均重要性。
- 題目（`describe`）多一句：「兩個數值來自不同來源，要放在同一張圖上對照。」
- 調整模式照現有規則：只問含焦點欄位的組合，欄位集合一樣、圖型也一樣的圖不重複給。

### 5.6 標題和顯示名稱

- 自動標題：「銷售·amount 與 退貨·amount 依 date」。
- 套顯示名稱時，兩個數值也要換（`DashboardDataService.relabel` 現在不換 `measures`）。標題判斷「是不是自動產生的」照舊。

### 5.7 異常檢查

`HighlightSummarizer` 現在把三欄的資料當成「期別、系列、數值」，拿到兩個數值的圖會把 `a` 當成系列名稱。改成：

- 有 `measures` 時，兩個數值各當一條系列，系列名稱是欄位名稱（送給 JEV 的是原始名稱）。
- `metric` 寫成「銷售·amount、退貨·amount」。
- 其他規則照舊：只比已經結束的期；空值當 0。

## 6. 畫面

### 6.1 合併表單

- 「方式」變成三個選項：疊加（欄位一樣的資料接起來）／對照（數值依來源分開比較）／查表（用主檔補欄位）。選對照時送出 `op: "union"`、`compare: true`。
- 對照的對應表：
  - 日期和文字欄位照疊加的規則，同名自動對上。
  - 數字欄位依來源拆開，每個來源的每個數字欄位各一列，名稱是「來源名·欄位」，只對應那一個來源。
  - 數字欄位對應到兩個以上來源的那一列標紅：「對照時數字欄位只能對應一個來源」。
  - 切換疊加和對照時，對應表照新的方式重排。
- 名稱預設「銷售／退貨 對照」，使用者改過就不再自動更新（跟疊加一樣）。
- 「來源」選單選滿 5 個之後，其他選項停用，不用等按預覽才由後端擋。疊加和對照都一樣。

### 6.2 圖表

- 長條圖和折線圖拿到三欄資料（`[x, a, b]`）時畫兩條系列，下方加圖例，系列名稱用 dimensions（已經換成顯示名稱）。長條圖並排，不堆疊。
- 雙 Y 軸：兩個數值各自的最大絕對值都大於 0，而且大的除以小的超過 10，就改用左右兩條 Y 軸，`b` 用右軸，兩條軸都標數值名稱。其他情況共用一條 Y 軸。
- `null` 不畫：折線斷開，長條留空。
- `ChartCard` 的數字縮寫（`compactValueAxis`）要能處理兩條 Y 軸（`yAxis` 是陣列）。

### 6.3 資料來源清單

說明列寫「對照：銷售、退貨 · 5 個欄位 · 0 個敏感」，圖示和「合併」標籤跟其他合併來源一樣。

## 7. API

不新增端點。

- `POST /api/datasources/merged/preview`、`POST /api/datasources/merged` 的 `merge` 可以帶 `compare: true`。
- `GET /api/datasources` 回傳的 `merge` 會帶 `compare`。
- 卡片的 `mapping` 可以帶 `measures`（5.3）。存檔、預覽照 `UniversalTransformer.problem` 驗證。

## 8. 錯誤處理

驗證失敗一律回 400，訊息寫中文：

- 5.1 的兩條。
- 長條圖、折線圖同時有 `value` 和 `measures`：「value 和 measures 只能擇一」。
- `measures` 不是剛好 2 個、有空白、兩個相同：「兩個數值的圖需要剛好兩個不同的 measures」。
- 有 `measures` 又用 `aggregate: none`：「兩個數值的圖不能用 aggregate none」。

其他照 B1 第 9 節。

## 10. 預設決定（2026-09-28 已確認）

下表是審閱時確認的預設：

| 項目 | 預設 | 另一種做法 |
|---|---|---|
| 數值欄位 | 強制依來源分開（已確認） | 只是畫面預設，可以手動併欄 |
| 某組缺一邊 | 空白（已確認） | 補 0 |
| 對照組合排序 | 焦點之後優先（已確認） | 照重要性跟其他組合一起排 |
| 對照的來源數量 | 2～5 個（已確認） | 只能 2 個 |
| 雙 Y 軸 | 最大絕對值差超過 10 倍才用 | 一律雙軸 |
| 兩個數值的圖型 | 折線、長條 | 再加圓餅以外的其他圖型 |
| 誰會多出對照組合 | 只有對照來源 | 所有合併來源（B1 第 12 節原本的寫法） |
| 對照來源的來源欄 | 不拿來畫圖 | 當一般欄位 |
| 計數只算非空值 | 所有來源 | 只限兩個數值的圖 |

## 11. 之後的子專案怎麼接

- **B3 比率**：計算指標＝分子÷分母，每一組先各自加總再相除。對照組剛好可以當分子和分母（退貨率＝`退貨·amount`÷`銷售·amount`），B3 可以直接用 5.3 的分組結果，在每一組算完兩個加總之後再除。一般來源同一份資料裡的兩個數值也能算，不限對照來源。
