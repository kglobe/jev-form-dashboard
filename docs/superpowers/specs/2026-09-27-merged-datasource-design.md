# JEV 儀表板：合併來源的疊加與查表（設計）

日期：2026-09-27
前提：主設計見 `docs/superpowers/specs/2026-09-23-jev-dashboard-design.md`。每張圖各自一個來源見 `docs/superpowers/specs/2026-09-27-multi-source-dashboard-design.md`（子專案 A）。本文件只寫這次新增和改變的部分。

## 1. 目的

高階主管的儀表板常要把幾份資料合起來看。這次先做兩種合併：

1. **疊加**：把欄位一樣的幾份資料接成一份，例如北區 Excel 接南區 Excel，或每月一個檔。
2. **查表**：用主檔替主來源補欄位，例如退貨單拿產品代碼去對產品主檔，補上產品類別和負責業務。

合併的結果是一種新的資料來源（`kind = merged`）。載入時才合併，輸出的資料列跟一般來源長得一樣，所以 JEV 分析、轉換器、異常檢查都不用改；敏感欄位和顯示名稱只多了繼承規則（第 6 節）。

後面還有兩個子專案，各自另寫 spec，等這份做完才開始：

- **B2 對照**：同一張圖上比兩個來源的數字，例如每月銷售額對退貨額。
- **B3 比率**：計算指標，例如退貨率＝退貨額÷銷售額。

## 2. 範圍

做：

- 資料來源種類 `merged`：疊加、查表兩種定義，定義存在 `datasource.merge_json`。
- 合併來源可以再拿去合併，最多三層。
- 合併前預覽：筆數、提示、前 20 列。
- 顯示名稱和敏感設定從輸入來源繼承；敏感設定之後也會跟著輸入來源變。
- 「新增來源」對話框加一個「合併」分頁。

不做：

- B2 的對照模式和一張圖兩個數值、B3 的計算指標。
- 編輯或刪除合併定義。現在所有資料來源都不能刪，合併來源也一樣；定義錯了就建一個新的。
- 快取合併結果、改用 SQL 在資料庫裡合併。
- 多對多連接、full outer join、只取部分資料列的篩選條件。

## 3. 使用情境

| 情境 | 方式 | 輸入 | 結果 |
|---|---|---|---|
| 全公司營收 | 疊加 | 北區營收、南區營收（欄位相同） | 一份資料，多一欄「來源」標出每列來自哪區 |
| 月檔合併 | 疊加 | 7 月、8 月、9 月退貨（有一個月欄位叫 `area`，其他月叫 `region`） | `area` 對應到 `region`，併成同一欄 |
| 退貨依產品類別 | 查表 | 主來源：R7 Excel 退貨；主檔：產品主檔；對接欄位 `product` = `code` | 退貨每一列補上 `category`、`owner` |
| 先查表再疊加 | 巢狀 | 兩份各自查表過的合併來源 | 第二層疊加 |

## 4. 資料模型

### 4.1 資料庫

Migration 編號要跟 A 錯開：暫定 A 用 `V2`、這份用 `V3`。哪一份先合併進 main 就用 `V2`，後合併的那份在合併前把檔名改成下一號。Flyway 不接受版本號比已套用的 migration 還小的新檔，順序錯了會驗證失敗。

```sql
alter table datasource add column merge_json jsonb;
alter table datasource drop constraint datasource_kind_check;
alter table datasource add constraint datasource_kind_check check (kind in ('upload', 'api', 'merged'));
alter table datasource add constraint datasource_merge_json_check check ((kind = 'merged') = (merge_json is not null));
```

`datasource_kind_check` 是 `V1__init.sql` 行內 check 的預設名稱（`<表>_<欄位>_check`）。

`Datasource` record 多一個 `merge` 欄位（合併定義），一般來源是 `null`，JSON 不輸出。

### 4.2 疊加定義

```json
{
  "op": "union",
  "inputs": ["<北區 id>", "<南區 id>"],
  "columns": [
    { "name": "region", "from": { "<北區 id>": "region", "<南區 id>": "area" } },
    { "name": "amount", "from": { "<北區 id>": "amount", "<南區 id>": "amount" } },
    { "name": "reason", "from": { "<南區 id>": "reason" } }
  ],
  "sourceColumn": "來源"
}
```

- `inputs`：2～5 個不重複的來源，順序就是資料列的順序。
- `columns`：輸出欄位和順序。`from` 寫每個輸入來源用哪一欄提供這個輸出欄位，至少要列一個；沒列在 `from` 裡的輸入來源，這欄是空的。
- `sourceColumn`：多出來那一欄的名稱。這欄標出每一列來自哪個輸入來源，值是那個來源在載入當下的名稱，放在最後一欄。

### 4.3 查表定義

```json
{
  "op": "lookup",
  "main": "<退貨 id>",
  "lookup": "<產品主檔 id>",
  "keys": [{ "main": "product", "lookup": "code" }],
  "bring": [
    { "name": "category", "from": "category" },
    { "name": "產品主檔·owner", "from": "owner" }
  ]
}
```

- `main`、`lookup`：主來源和主檔，不能是同一個。
- `keys`：1～3 組對接欄位，所有組都相等才算對上。
- `bring`：要從主檔補上的欄位。`name` 是輸出名稱，不能跟主來源的欄位或其他補上的欄位同名。
- 輸出欄位：主來源全部欄位照原本順序，後面接 `bring`。

## 5. 合併規則

### 5.1 疊加

- 每個輸入來源的每一列產生一列輸出：`from` 有列這個輸入來源就取值，沒列就不放這個 key（跟上游省略空值的做法一致，轉換器的「欄位還在不在」判斷照舊）。
- 同一個輸出欄位對應到的輸入欄位，型別（`number`／`date`／`string`）必須相同，不同就拒絕，不偷偷轉型。例如「`region` 在北區是文字、在南區是數字，不能併成同一欄」。
- 沒有任何 `from` 用到的輸入欄位會被丟掉。
- 資料列順序：先照 `inputs` 的順序，同一個來源內照原本的順序。

### 5.2 查表

- 用 left join：主來源有幾列，輸出就有幾列。
- 每組對接欄位兩邊的型別必須相同。
- 比對用正規化後的值轉成字串：數字去掉多餘的小數零（`1` 和 `1.0` 算相同），日期用 ISO 字串，文字照原樣比。只要有一個對接欄位是空值，這列就不算對上。
- 主檔的對接值重複時，用排最前面的那一列，預覽時提示有幾個重複的對接值。
- 對不上的主來源列，補上的欄位是空的，預覽時提示有幾筆對不上。
- 主檔的對接欄位不會自動補進來，要的話另外勾。

### 5.3 巢狀

- 輸入來源可以是合併來源。上傳和外部 API 算第 0 層，合併來源的層數是輸入來源的最大層數加 1，最多 3 層。
- 定義不能編輯，輸入來源在建立時就必須存在，所以不會形成循環。
- 同一個輸入來源在巢狀結構裡出現兩次，就會被載入兩次。
  `ponytail:` 目前不去重，等巢狀合併常見、載入變慢時，再在同一次 `load` 裡加快取。

### 5.4 筆數上限

- 合併後的筆數必須在 1 到 `jev.upload.max-rows`（100,000）之間，預覽和建立時超過就拒絕。
- 外部 API 輸入後來變多、載入時超過上限，就回傳跟一般來源相同的「資料有 N 筆，超過上限 100000 筆」。
- 轉換器本來就在記憶體裡聚合，合併也在記憶體裡做，上限跟主設計 6.1 一樣。

### 5.5 載入

`DatasourceService.load` 遇到 `merged` 時，先照定義載入每個輸入來源（遞迴呼叫 `load`，所以輸入來源已經正規化好了），再交給純函式 `MergeEngine.union` 或 `MergeEngine.lookup` 合併，最後檢查筆數。合併結果不再依 schema 正規化一次。

不做成 `DataSourceProvider`：provider 拿不到使用者，也不能回頭呼叫 `DatasourceService.load`，否則會變成循環依賴。

## 6. 欄位設定

### 6.1 Schema

建立時，拿合併後的資料列跑一次 `SchemaInference.infer`，算出型別、相異值數量、樣本、最大值和最小值，存進 `schema_json`。之後就不再重算，跟外部 API 來源一樣是建立當下的快照。

### 6.2 顯示名稱

- 疊加：照 `inputs` 順序，取第一個有設定顯示名稱的對應欄位。`sourceColumn` 沒有顯示名稱。
- 查表：主來源的欄位沿用主來源的顯示名稱，`bring` 的欄位沿用主檔那一欄的顯示名稱。
- 繼承後顯示名稱重複時，後面那一欄不繼承，免得違反現有「顯示名稱不能重複」的規則。
- 建立之後可以照常在欄位表上修改。

### 6.3 敏感欄位

敏感設定是資料外送的防線（主設計 6.3），不能因為多包一層合併就消失：

- 合併來源自己勾了，或任何一個提供這欄的輸入欄位是敏感的，這欄就算敏感。提供這欄的輸入欄位：疊加是 `from` 裡的欄位；查表時，主來源的欄位看主來源的同名欄位，`bring` 欄位看 `from` 指到的主檔欄位；巢狀時一路往下找。
- 讀取合併來源時（`get`、`list`、`load`）即時算，不在建立時凍結。之後在輸入來源多勾一個敏感欄位，合併來源馬上跟著變。
- 繼承來的敏感設定在合併來源上不能取消。`FieldSchema` 多一個唯讀的 `sensitiveFrom`（讓這欄變敏感的輸入來源名稱），只在讀取時填入，不存進資料庫。畫面上的開關停用，提示「在『北區』標為敏感，要改請到那個來源」。
- 查表的對接欄位只拿來比對，沒被 `bring` 就不會出現在輸出裡，也不會影響敏感設定。

## 7. API

| 方法 | 路徑 | Body | 回傳 |
|---|---|---|---|
| POST | `/api/datasources/merged/preview` | `{ name, merge }` | `{ schema, rows, rowCount, warnings }` |
| POST | `/api/datasources/merged` | `{ name, merge }` | `Datasource` |

- 預覽不存檔，`rows` 是前 20 列，`warnings` 是中文提示的陣列：
  - 疊加：「`reason` 只有南區有，其他來源的列這欄是空的」。
  - 查表：「主檔有 3 個對接值重複，用排最前面的那一列」、「12 筆對不到主檔，補上的欄位是空的」。
- 建立時照同一套規則再驗證、再合併一次，因為輸入來源可能在預覽之後變了。
- `GET /api/datasources` 的清單裡，合併來源會帶 `kind: "merged"` 和 `merge`。
- `PATCH .../sensitive`、`PATCH .../labels` 對合併來源照常可用，敏感設定依 6.3 的規則處理。

## 8. 畫面

### 8.1 新增來源對話框

「新增來源」對話框在「上傳檔案」、「外部 API」後面加一個「合併」分頁。切到這個分頁時，對話框加寬到 760px，對應表才放得下。表單內容獨立成 `MergeForm.vue`，因為 `DatasourcePanel.vue` 已經 327 行了。

1. **方式**：疊加（欄位一樣的資料接起來）／查表（用主檔補欄位）。
2. **疊加**：
   - 「來源」多選，2～5 個。
   - 對應表：第一欄是輸出欄位名稱（可以改），後面每個輸入來源各一欄，每格是下拉選單，列出那個來源的欄位（附型別圖示）和「（無）」。
   - 列表預設是所有輸入來源的欄位名稱聯集，照來源順序排；同名的欄位自動對上。
   - 每一列可以用「✕」刪除，也可以「新增一欄」。
   - 型別對不上的那一列直接標紅，寫出原因。
   - 「來源欄名稱」預設「來源」。
3. **查表**：
   - 「主來源」和「主檔」各一個下拉選單，主檔選單不列出已經選為主來源的那個。
   - 對接欄位：「主來源欄位 = 主檔欄位」，1～3 組，可以增減。
   - 「補上的欄位」：列出主檔欄位的勾選清單（對接欄位預設不勾），每個欄位旁邊都能改輸出名稱。預設用原本的名稱，跟主來源欄位同名時改成「主檔名·欄位」。
4. **名稱**：疊加預設「北區＋南區」，查表預設「退貨（補產品主檔）」，使用者改過就不再自動更新。
5. **預覽**：按「預覽」後顯示筆數、提示和前 20 列（表格可以左右捲動）。定義一改，預覽就清掉；只有預覽成功、而且顯示的是目前的定義時，「建立」才能按。

### 8.2 資料來源清單和欄位表

- 合併來源的圖示用 `mdi-set-merge`，標籤寫「合併」。
- 說明列：「疊加：北區、南區 · 12 個欄位 · 2 個敏感」或「查表：退貨 ← 產品主檔（product = code）· 11 個欄位 · 0 個敏感」。來源名稱從清單裡查，查不到就顯示「（已不存在）」。
- 欄位表：繼承來的敏感開關停用，並顯示 6.3 的提示。
- 「用這個來源製圖」照舊，製圖頁不用改。

## 9. 錯誤處理

驗證失敗一律回 400，訊息寫中文而且要具體：

- 疊加的輸入來源不是 2～5 個，或有重複。
- 查表的主來源和主檔是同一個、對接欄位不是 1～3 組。
- 欄位名稱空白、重複、超過 50 字；`sourceColumn` 跟其他欄位同名；`bring` 跟主來源欄位同名。
- `from`、`keys` 指到輸入來源裡沒有的欄位：「北區沒有 `area` 這個欄位」。
- 型別對不上（5.1、5.2）。
- 超過三層（5.3）。
- 合併後的筆數是 0 或超過上限（5.4）。

其他情況：

- 輸入來源不是這位使用者的，或找不到：404「找不到資料源」，跟現有訊息一樣，不透露那個來源存不存在。
- 載入時外部 API 輸入失敗：照現有外部 API 的錯誤回傳，合併來源不另外包裝。
- 外部 API 輸入後來少了某個欄位：輸出那欄變成空的，圖表照現有的「欄位不見了」處理。

## 11. 預設決定（請確認）

以下是先訂的預設，審閱時可以改：

| 項目 | 預設 | 另一種做法 |
|---|---|---|
| 型別對不上 | 拒絕合併 | 自動轉成文字 |
| 主檔對接值重複 | 用第一列，預覽時提示 | 直接拒絕 |
| 建立前一定要預覽 | 要 | 可以直接建立 |
| 疊加最多幾個來源 | 5 個 | 不設限 |
| 巢狀層數 | 最多 3 層 | 不能巢狀 |
| 合併定義 | 不能編輯、不能刪除 | 可以編輯；刪除要跟所有資料來源的刪除一起做，另開 backlog 項目 |

## 12. 之後的子專案怎麼接

- **B2 對照**：疊加多一個「對照」選項，日期和分類欄位合併，數值欄位分開放（`銷售·amount`、`退貨·amount`），任何圖都不會把兩個來源的數字加在一起。折線圖和長條圖要能放兩個數值，JEV 也要多出合併來源專用的組合。計數聚合改成只算非空值，疊加後才不會把其他來源的列也算進去。
- **B3 比率**：計算指標＝分子÷分母，每一組先各自加總再相除。任何來源都能加，不限合併來源。
