# JEV 儀表板：刪除資料來源（設計）

日期：2026-09-30
前提：合併來源見 `2026-09-27-merged-datasource-design.md`（B1），一份儀表板放多個來源見 `2026-09-27-multi-source-dashboard-design.md`（A）。本文件只寫這次改變的部分。

## 1. 問題

資料來源建立之後就刪不掉。合併定義也不能改，定義建錯了只能另建一個，清單越積越長。backlog 裡有兩項跟這件事有關：「編輯、刪除合併來源的定義」（P3），以及「輸入來源不見時，合併來源的敏感設定要 fail closed」（P2）。這次處理刪除和 fail closed，編輯不做，能刪掉就能重建。

## 2. 規則

- 上傳檔案、外部 API、合併來源都能刪，規則相同。
- 有合併來源直接拿它當輸入時，不能刪，要先刪掉那些合併來源。間接用到的不用另外算，因為中間那一層會先被擋下。
- 有儀表板的卡片用到它時，確認後照樣刪除。儀表板本身不動，那些卡片改為顯示「資料來源已刪除」，使用者可以按 ✕ 自己移除。
- 刪除之後無法復原。上傳檔案的資料列跟著刪掉；外部 API 的 header 只存了 `${DS_XXX}` 這種寫法，不存秘密本身，沒有其他東西要清。
- 只能刪自己的來源。別人的來源和找不到的來源一樣，回 404。

## 3. API

### 3.1 `GET /api/datasources/{id}/usage`

```json
{
  "mergedBy": [{ "id": "…", "name": "北區＋南區" }],
  "dashboards": [{ "id": "…", "name": "銷售總覽", "charts": 3 }]
}
```

- `mergedBy`：輸入來源（`MergeDefinition.inputIds`）裡有這個 id 的合併來源，照清單順序排。
- `dashboards`：`layout` 裡有卡片的 `datasourceId` 是這個 id 的儀表板，`charts` 是這種卡片有幾張，明細表也算。卡片用的是「用到它的合併來源」時不算，因為那種情況一定先被 `mergedBy` 擋住。
- 沒有人用到時，兩個都是空陣列。

### 3.2 `DELETE /api/datasources/{id}`

- 成功回 204。
- `mergedBy` 不是空的時候回 409：「「銷售」是這些合併來源的輸入，要先刪掉：北區＋南區、銷售對退貨」。前端會先查 usage，這一步是後端自己再擋一次。
- 找不到，或不是自己的來源，回 404「找不到資料源」。

`ponytail:` 檢查和刪除之間沒有上鎖。同一個時間點另外建立一個拿它當輸入的合併來源，還是可能留下斷掉的定義；那時由 4.3 的 fail closed 確保欄位不會被當成不敏感。要是出現多人同時操作的情況，再把 `DatasourceService.delete` 包成交易、鎖住使用者的來源。

## 4. 後端其他改動

### 4.1 `/data`：卡片的來源找不到

`DashboardDataService.sources` 載入失敗時，原本會查來源名稱：查得到就回 `SOURCE_FAILED` 並帶上名稱，查不到就回 `SOURCE_FAILED` 但名稱是 `null`。改成查不到來源時回新的錯誤 `SOURCE_DELETED`（`ChartData.sourceDeleted`），不帶名稱。

「全部來源都載入失敗就整份報錯」這條規則不算已刪除的來源。只有在每個來源都失敗、而且沒有一個是被刪除的時候，才丟出第一個錯誤。不這樣做的話，來源全刪光的儀表板會整份打不開，連 ✕ 都按不到。

預覽（`POST /api/dashboards/preview/data`）用的是同一套邏輯，一起改。

### 4.2 `PUT /api/dashboards/{id}`：有已刪除來源的儀表板照樣能存

現在每次存檔都會對每張卡片的來源呼叫 `datasources.get`，所以來源刪掉之後，拖拉版面、移除卡片都會回 404。改成只檢查資料庫裡目前版面沒有的來源，也就是這次存檔新帶進來的來源。前端透過這支 API 只會拖拉或刪卡片，不會加入新的來源（加圖走 `POST /{id}/charts`），所以正常流程不會遇到新來源。

### 4.3 敏感設定 fail closed

`DatasourceService.sensitiveFrom` 找不到輸入來源時，原本是 `continue` 跳過。改成回傳「（已刪除的來源）」，這一欄就算是繼承來的敏感欄位，開關停用。

有了第 2 節的規則，正常流程不會走到這裡，只有 3.2 提到的同時操作才會。所以欄位表的提示照現有文案，會寫成「在『（已刪除的來源）』標為敏感，要改請到那個來源」，這次不另外改。

### 4.4 不用改的地方

- 異常檢查：`JevController.highlight` 從來源清單讀敏感設定，清單裡找不到的來源，卡片本來就不送檢查。
- 資料庫：`datasource_rows` 已經設了 `on delete cascade`；儀表板對來源的引用存在 `config_json` 裡，沒有外鍵（V2 刪掉了）。不需要新的 migration。
- 分析、建立儀表板、加到既有儀表板：來源不存在時本來就回 404「找不到資料源」。

## 5. 畫面

### 5.1 刪除按鈕

資料頁右側來源詳細的標題列，「用這個來源製圖」旁邊加一顆「刪除來源」按鈕（`mdi-delete-outline`）。放在詳細區、不放在左邊清單的每一列，比較不會誤按。

### 5.2 對話框

按下去先打 usage，請求還沒回來之前按鈕停用。

被合併來源用到時：

- 標題「無法刪除」。
- 內文「「銷售」是下面這些合併來源的輸入，要先刪掉它們：」，接著逐行列出名稱。
- 只有一顆「知道了」。

其他情況：

- 標題「刪除資料來源」。
- 內文「確定刪除「銷售」？刪除後無法復原。」
- 有儀表板用到時，再加一段「下面這些儀表板有用到它的圖，刪除後會顯示「資料來源已刪除」，可以再按 ✕ 移除：」，逐行列出「銷售總覽（3 張圖）」。
- 按鈕「取消」、「刪除」，刪除用錯誤色，樣式跟「刪除儀表板」、「移除圖表」一樣。
- 刪除失敗（例如這段時間有人建了合併來源而回 409）時，錯誤訊息顯示在對話框裡，對話框不關。

刪除成功後關掉對話框，重新讀來源清單。原本選的來源不在清單裡，會照現有邏輯改選第一個。

### 5.3 卡片

`SOURCE_DELETED` 的卡片顯示警告「資料來源已刪除，可以按右上角 ✕ 移除這張圖」。其他卡片照常顯示。

依據那一行不用改：名稱是從 `/data` 回傳的 `source` 來的，已刪除的來源沒有名稱，照現有規則不加括號。這些卡片都移除之後，那一組依據會跟著拿掉（A spec 3.4）。

### 5.4 製圖頁

不用改。製圖頁回到畫面時會重讀來源清單，原本選的來源不見了，就清掉預覽、改選第一個（`ChartBuilder.loadList`）。

## 6. 測試

後端：

- usage：`mergedBy` 只列直接用到的合併來源；`dashboards` 的張數包含明細表；沒有人用到時兩個都是空陣列。
- 刪除：被合併來源用到時回 409 並列出名稱，來源還在；成功刪除後，上傳來源的資料列也不在了；別人的來源回 404。
- `/data`：卡片的來源刪掉後回 `SOURCE_DELETED`，其他卡片照常；所有卡片的來源都被刪掉時不會整份報錯；原本的「全部載入失敗就整份報錯」照舊。
- 存檔：版面裡有已刪除來源的卡片時，拖拉、移除卡片都存得進去；帶進一個不存在、原本版面也沒有的來源，照舊回 404。
- fail closed：合併來源的輸入來源不見時，那些欄位變成敏感，`sensitiveFrom` 是「（已刪除的來源）」。

前端：

- 被合併來源用到：跳出「無法刪除」，列出名稱，沒有刪除按鈕。
- 被儀表板用到：確認框列出儀表板和張數；按「刪除」會呼叫 DELETE、重讀清單。
- 刪除失敗時，錯誤留在對話框裡。
- `SOURCE_DELETED` 的卡片顯示「資料來源已刪除」。

瀏覽器（自己用 Chrome 操作，用另一個使用者 ID 準備資料，不動 `demo-user` 的測試資料）：

1. 刪一個被合併來源用到的來源：看到「無法刪除」，來源還在。
2. 刪一個被儀表板用到的來源：確認框列出儀表板；刪掉之後打開儀表板，那些卡片顯示已刪除，其他卡片正常；拖拉一張卡片、按 ✕ 移除已刪除的卡片，都存得進去。
3. 再刪掉合併來源，然後刪掉它原本的輸入來源：這次可以刪。
4. 最後在 `demo-user` 下刪掉 2026-09-30 示範時建的「示範疊加：民國年訂單＋sales」。

## 7. 決定（2026-09-30 已確認）

| 題目 | 選擇 | 沒選的 |
|---|---|---|
| 刪除範圍 | 所有來源 | 只有合併來源 |
| 被合併來源用到 | 擋下並列出 | 連同合併來源一起刪 |
| 被儀表板卡片用到 | 確認後照刪，卡片顯示「資料來源已刪除」 | 擋下要先移除卡片；連卡片一起移除 |
| 編輯合併定義 | 不做，刪掉重建 | 另外做編輯 |
