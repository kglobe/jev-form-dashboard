# JEV 儀表板：更新來源的資料（設計）

日期：2026-10-02
前提：上傳來源見 `2026-09-23-jev-dashboard-design.md`，合併來源見 `2026-09-27-merged-datasource-design.md`（B1），刪除來源見 `2026-09-30-delete-datasource-design.md`。本文件只寫這次改變的部分。

## 1. 問題

每次上傳都會變成一個新的來源，合併定義又不能改。每月多一個檔，就要多建一個來源，再把用到舊來源的合併來源整串刪掉重建，圖也得重做。這次讓上傳的來源可以換資料：上傳新檔時選「整份覆蓋」或「接在後面」，用到它的圖和合併來源下次載入就會是新的資料。

## 2. 規則

### 2.1 哪些來源能更新

- 只有上傳檔案的來源（`kind = upload`）。外部 API 每次載入都會重抓，合併來源每次載入都會照定義重新合併，兩種都用不到這個功能。
- 只能更新自己的來源。別人的來源跟找不到的來源一樣，回 404「找不到資料源」。

### 2.2 欄位要跟原本一樣

- 新檔案的欄位名稱要跟原本是同一組，順序可以不同。
- 不一樣時回 400，並列出差異：「欄位跟原本的不一樣：少了 region、qty；多了 note」。少的照原本的欄位順序列，多的照新檔案的順序列；只有一邊有差異時，只寫那一邊。
- 不能藉著更新來增減欄位。欄位一變，圖的設定、比率、合併定義都可能對不上；遇到這種情況，請另外上傳成新的來源。

### 2.3 型別不變

- 更新不會改變欄位的型別。原本是數字或日期的欄位，新檔案裡每個有值的格子都要符合那個型別，整欄空白沒關係；文字欄位什麼都收。
- 不符合時回 400：「欄位「amount」原本是數字，新檔案裡有不是數字的值」。日期欄位的訊息是「原本是日期，新檔案裡有不是日期的值」。好幾欄都不符合時，只回報原本欄位順序裡的第一欄。
- 判斷規則跟第一次上傳推斷型別時一樣，千分位、民國年、8 碼日期都認得。新的資料列照原本的 schema 整理，所以文字欄位裡的 `5` 會存成文字 `"5"`，不會變成數字。Excel 的數字格放在文字欄位裡同樣存成 `"5"`，不是 `"5.0"`（第一次上傳也一樣）；CSV 和 Excel 輪流拿來更新，同一個代碼不會分成兩類。

### 2.4 整份覆蓋、接在後面

- 整份覆蓋（`replace`）：來源的資料列換成新檔案的資料列。
- 接在後面（`append`）：新檔案的資料列接在原本的後面，`row_no` 從原本的筆數往下編。
- 檔案只有標題列、沒有資料列的話，兩種方式都回 400「沒有資料列」，資料和合併來源的筆數都不動。
- 更新後的總筆數不能超過 `jev.upload.max-rows`，接在後面時算原本加上新的。超過時回 400「資料有 N 筆，超過上限 M 筆」。
- 後端不檢查重複：同一個月的檔案接了兩次，資料就會有兩份。接錯了，用整份覆蓋重來。

### 2.5 欄位統計

- 相異值數、樣本、日期的最早和最晚，都用更新後的整份資料重算，算法跟第一次上傳一樣：整份覆蓋只看新檔案，接在後面看原本加上新的。
- 顯示名稱、敏感設定、比率完全不動。
- 整份覆蓋用檔案讀出來的值算。拿第一次上傳的那個檔案再整份覆蓋一次，統計會一模一樣：樣本照檔案裡的寫法（`2024/3/1`、`1,200`），寫法不同的值各算一個相異值。
- 接在後面時，舊的資料列只剩整理過的值，所以整份資料都用整理過的值算。數字去掉千分位和尾端多餘的 0（`1,200` 寫成 `1200`，`1500.50` 寫成 `1500.5`），日期一律寫成 `2024-03-01`，時間捨去。寫法不同、值相同的只算一個相異值，像 `1,200` 和 `1200`、`2024/3/1` 和 `2024-03-01`、同一天的 10:00 和 11:00。相異值數可能比第一次上傳時少，值本身不變。
- 數字樣本不會寫成 `1200.0`，Excel 的數字格也一樣。0 開頭的代碼（`007`）屬於文字欄位，照原樣顯示。

### 2.6 用到它的圖和合併來源

- 圖每次載入都讀資料庫裡的資料列，合併來源每次載入都重新合併，所以不用另外通知，下次打開就是新的資料。
- 直接或間接用到它的合併來源（最多 3 層），`row_count` 都清成 null。分析時遇到 null，照 `JevController.analyze` 原本的規則載入資料重新算筆數；對欄位（`/api/jev/mapping`）時不送筆數。
- 合併來源自己存的欄位統計（樣本、相異值數、日期範圍）是建立時算的，這次不重算，只會讓分析時給 JEV 的提示舊一點。`ponytail:` 要準的話，再改成更新時一併重算用到它的合併來源。

## 3. API

### 3.1 `POST /api/datasources/{id}/rows`

multipart：

| 欄位 | 必填 | 說明 |
|---|---|---|
| `file` | 是 | `.csv`、`.xlsx`、`.xls`，規則跟上傳一樣（50 MB、筆數上限） |
| `mode` | 是 | `replace` 或 `append` |
| `sheet` | 否 | Excel 的工作表名稱，沒填就用第一個 |

- 成功回 200，內容是更新後的來源，格式跟 `GET /api/datasources` 清單裡的一筆相同，`rowCount` 是新的筆數。
- 錯誤一律是 `{"error": "…"}`：
  - 沒帶 `mode`：400「缺少參數：mode」；沒帶 `file`：400「缺少參數：file」。
  - `mode` 不是這兩個值：400「更新方式只能是 replace（整份覆蓋）或 append（接在後面）」。
  - 找不到，或不是自己的來源：404「找不到資料源」。
  - 不是上傳來源：400「只有上傳的檔案可以更新資料」。
  - 2.2、2.3、2.4 的訊息，以及副檔名、CSV 格式、找不到工作表這些跟上傳相同的錯誤。
- 先檢查 `mode` 和來源，再解析檔案，所以伺服器不會替別人的來源解析檔案。

## 4. 後端

### 4.1 流程

`DatasourceService.reload`：

1. 檢查 `mode`，查來源（找不到回 404），檢查 `kind`。
2. 解析檔案。跟上傳共用 `parse`，在交易外進行，解析大檔案時不會占著資料庫連線。檔案沒有資料列就擋下（2.4）。
3. 檢查欄位（2.2）和型別（2.3），用原本的 schema 整理新的資料列。
4. `DatasourceRepository.locked` 開一個交易並鎖住來源，接著依序：重讀來源；接在後面時讀出原本的資料列；檢查筆數；整份覆蓋時刪掉舊的資料列；寫入新的資料列；寫入重算後的 schema（2.5：整份覆蓋用檔案讀出來的值，接在後面用整理過的整份資料）和 `row_count`；把用到它的合併來源的 `row_count` 清成 null。
5. 交易結束後再讀一次來源，回傳。

第 4 步裡任何一步失敗，整個交易都會退回，資料列、統計、筆數維持原樣。

### 4.2 同時更新

- 用 `select id from datasource where id = ? for update` 鎖住來源那一列。同一個來源同時有兩個更新時，後到的會等前一個 commit 之後才讀現有的資料列，兩次接在後面不會撞到同一個 `row_no`，筆數上限也算得對。
- 鎖住之後重讀來源。解析檔案的期間，使用者可能在另一個分頁改了顯示名稱或敏感設定，寫回 schema 時要用最新的；來源要是已經被刪掉，就回 404。
- 改顯示名稱（`setLabels`）和敏感設定（`markSensitive`）也走 `locked`，先鎖住來源再讀 schema。更新正在進行的話，就等更新 commit 之後才讀，寫回去的是新的統計加上這次的修改。不上鎖的話，在更新途中讀到舊 schema 的那一邊，會在更新寫完後把舊的統計整份蓋回去。
- `ponytail:` 只鎖這個來源。在同一時間拿它建立合併來源的話，合併來源可能記下舊的筆數，影響的只有分析時給 JEV 的筆數；要精準的話，再改成一起鎖住使用者的所有來源。

### 4.3 不用改的地方

- 資料庫：不需要新的 migration，資料列、`schema_json`、`row_count` 都是現有欄位。
- 異常檢查：`HighlightService` 拿每張圖送給 JEV 的資料摘要當快取 key 的一部分，資料一變，key 跟著變，就會重新問 JEV。
- 對欄位（`/api/jev/mapping`）本來就不快取。
- 載入用的 `Loader` 只在一次請求裡有效，不會跨請求。
- 前端沒有快取資料。已存的儀表板每次打開都重抓 `/data`，資料頁和製圖頁回到畫面時都會重讀來源清單。製圖頁上還沒存的預覽是已經畫好的圖，不會自己重畫；存成儀表板之後打開，就是新的資料。

## 5. 畫面

### 5.1 按鈕

資料頁右側來源詳細的標題列，上傳來源多一顆「更新資料」（`mdi-database-refresh-outline`），放在「刪除來源」左邊。外部 API 和合併來源沒有這顆按鈕。

### 5.2 對話框

- 標題「更新資料」。
- 說明兩行：「「銷售」目前有 12 筆資料。新檔案的欄位名稱要跟原本一樣。」和「更新後，用到它的圖和合併來源都會顯示新的資料。」
- 檔案欄（CSV / Excel，接受的副檔名相同）和「工作表（Excel 選填）」，跟新增來源的「上傳檔案」分頁一樣。
- 更新方式有「整份覆蓋」和「接在後面」，沒有預設值，還沒選之前「更新」按鈕是停用的。
- 沒選檔案、檔案超過 50 MB 時，跟上傳一樣先在前端擋下，顯示「請先選擇檔案」或「檔案太大，上限 50MB」。
- 後端回錯誤時，訊息顯示在對話框裡，對話框不關。
- 請求還沒回來之前，「更新」顯示載入中，再按也不會重送；「取消」停用，點對話框外面或按 Esc 也關不掉（`persistent`）。如果能關，請求失敗時錯誤沒地方顯示，成功時就算按了取消，資料還是換掉了。
- 每次打開都是空白的表單。

### 5.3 成功之後

關掉對話框，重讀來源清單，頁面上方顯示「已更新「銷售」：共 15 筆」。這則訊息可以按 ✕ 關掉，下次打開更新對話框時也會自動收起。萬一重讀清單失敗，錯誤顯示在頁面的錯誤列；這時更新本身已經成功了。

## 6. 測試

後端：

- service（用記憶體裡的 repository）：整份覆蓋、接在後面；`mode` 不對；別人的來源、不存在的來源回 404；外部 API、合併來源回 400；少欄位、多欄位；數字、日期欄位混進別的值；整欄空白可以；文字欄位的數字照文字存；CSV 來源接上 Excel，文字欄位裡的數字存成 `5`；只有標題列的檔案兩種方式都擋下，合併來源的筆數不動；接在後面時筆數上限算原本加新的；顯示名稱、敏感設定、比率不變；統計重算（日期最晚的一天、數字樣本是 1200、0 開頭的代碼）；拿第一次上傳的那個檔案整份覆蓋，統計一模一樣；兩層合併來源的 `row_count` 都清掉，沒用到它的不動，載入時讀到新的資料列。
- `SchemaInference`：Excel 的數字在樣本和文字欄位裡寫成 `1200`、`5`。
- repository（PostgreSQL）：接在後面時 `row_no` 往下編，整份覆蓋從 0 開始；寫入失敗時整個退回，舊的資料列、統計、筆數、合併來源的筆數都還在；兩個「接在後面」同時進來，兩個都成功，`row_no` 不重複；讀檔在交易外。另一個交易先鎖住來源，等「接在後面」和改顯示名稱（或敏感設定）都排在鎖後面才放開：顯示名稱和敏感設定都留著，統計是接在後面之後的。拿掉鎖或交易時，對應的測試會失敗。
- controller：回傳格式跟清單一樣，儀表板的 `/data` 讀到新的資料列；缺 `mode`、缺 `file`、`mode` 不對、副檔名不支援、別人的來源、合併來源、欄位不同、型別不符、超過筆數上限各自的錯誤訊息；Excel 讀指定的工作表，數字樣本寫成 1200；兩層合併來源的 `rowCount` 變成 null，沒用到的不變。上面那層只透過下面那層用到它，沒往上追的話這個測試會失敗。

前端：

- 只有上傳來源有「更新資料」。
- 對話框顯示筆數和說明；沒選更新方式時「更新」是停用的。
- 送出的 FormData 帶 `file`、`mode`、`sheet`，沒填工作表就不帶 `sheet`；成功後對話框關閉、重讀清單、顯示「已更新「…」：共 N 筆」；再打開是空白的表單。
- 後端的錯誤留在對話框裡；沒選檔案、檔案太大時不送出；請求中不能重送，「取消」停用、對話框關不掉，失敗的訊息留在對話框裡。
- api：`reloadDatasource` 用 POST 把 FormData 原樣送出。

瀏覽器（自己用 Chrome 操作，用另一個帳號準備資料）：

1. 上傳一份 CSV，拿它建一張圖和一個合併來源，再用這個合併來源疊一層。
2. 接在後面：筆數變多，圖和兩層合併來源打開後都看得到新的資料。
3. 整份覆蓋：只剩新檔案的資料。
4. 欄位不同、型別不符的檔案：錯誤顯示在對話框裡，資料不變。
5. 外部 API、合併來源沒有「更新資料」。

## 7. 決定（2026-10-02）

| 題目 | 選擇 | 沒選的 |
|---|---|---|
| 哪些來源能更新 | 只有自己的上傳來源 | 外部 API、合併來源也能更新 |
| 更新方式 | 整份覆蓋或接在後面，每次自己選，沒有預設值 | 只能整份覆蓋；預設接在後面 |
| 欄位不一樣 | 擋下，列出少了、多了哪些 | 自動增減欄位 |
| 型別 | 不變，新檔案不符合就擋下 | 照新檔案重新推斷 |
| 欄位統計 | 用整份結果重算，顯示名稱、敏感設定、比率不動 | 只看新檔案；不重算 |
| 樣本的寫法 | 整份覆蓋照檔案裡的寫法，跟第一次上傳一樣；接在後面用整理過的值（數字不帶千分位和多餘的 0，日期 `YYYY-MM-DD`） | 兩種都用整理過的值（拿同一個檔案整份覆蓋，樣本和相異值數也會變）；接在後面也照檔案的寫法（舊的資料列只剩整理過的值，做不到） |
| Excel 的數字放在文字欄位 | 存成 `5`，跟 CSV 一樣，第一次上傳也是；樣本也不寫 `.0` | 照 Excel 讀到的 `5.0` 存（CSV 和 Excel 輪流更新時，同一個代碼會分成兩類） |
| 只有標題列的檔案 | 兩種方式都回「沒有資料列」 | 接在後面時照樣成功（筆數沒變，合併來源的筆數卻被清掉） |
| 合併來源 | 載入時自然讀到新資料；直接、間接用到它的 `row_count` 清成 null | 更新時一併重算合併來源的筆數和統計 |
| 同時更新 | 鎖住來源那一列，後到的等前一個寫完 | 不鎖，讓主鍵擋下其中一個 |
| 改顯示名稱、敏感設定 | 也鎖住來源再讀 schema | 不鎖（更新途中改的話，舊的統計會被蓋回去） |
| 請求中關對話框 | 不行：「取消」停用，對話框 `persistent` | 可以關，請求在背景跑完 |
| migration | 不需要 | — |
