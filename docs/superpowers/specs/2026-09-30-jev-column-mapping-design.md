# JEV 儀表板：JEV 建議疊加的欄位對應（設計）

日期：2026-09-30
前提：合併來源見 `2026-09-27-merged-datasource-design.md`（B1），對照見 `2026-09-28-compare-datasource-design.md`（B2），JEV 的用法見 `docs/JEV智慧化產製儀表板的流程與方法.md`。本文件只寫這次新增的部分。

## 1. 問題

疊加和對照的對應表，只有欄位名稱一模一樣時才會自動對上。實際的資料常常一份用中文、一份用英文，或是同一件事叫法不同：民國年訂單的「訂單日期」「地區」「金額」，跟 sales.csv 的 `order_date`、`region`、`amount` 一格都對不上，得一格一格手動選，再把多出來的列刪掉（2026-09-30 示範時就是這樣）。

這次讓 JEV 判斷「哪兩個欄位是同一種資料」，把對應表先填好，使用者看過、改過，照舊要預覽才能建立。查表的對接欄位建議、合併方式建議不在這次範圍，見第 8 節。

## 2. 分工

跟分析一樣，JEV 只負責判斷，規則由後端決定：

- 只有型別相同的欄位才會出現在選項裡，文字欄位不可能配到數字欄位。
- 名稱已經一樣、自動對上的欄位不問。
- 信心不夠的答案不採用，同一個欄位被搶的時候照固定規則挑一個。
- JEV 不碰資料列，實際合併照舊由 `MergeEngine` 依定義執行，同樣的定義永遠得到同樣的結果。

## 3. 規則

### 3.1 跟誰比

第一個輸入來源是基準。第二個以後的每個來源，各自跟基準比，一次呼叫 JEV 問完。

`ponytail:` 只跟第一個來源比。有三個以上的來源時，基準沒有、只出現在第二或第三個來源的欄位，不會互相對起來，要自己選。等常遇到三個以上來源互相對不上時，再改成逐一累加比對（每加一個來源就多一輪 JEV 呼叫）。

### 3.2 問哪些欄位

對第二個以後的每個來源 B，逐一看 B 的每個欄位 c：

- 基準裡有同名欄位：不問，照現在的規則自動對上。
- 對照模式下，數字欄位不問，因為對照的數字欄位本來就依來源分開（B2 spec 6.1）。
- 候選是基準裡跟 c 同型別的欄位，但 B 裡有同名欄位的不算，因為它已經自動對上了。對照模式下候選也不含數字欄位。
- 沒有任何候選時不問。

### 3.3 題目

每個要問的欄位一題 `choice`，key 用索引（`map_<k>_<j>`：k 是 B 在輸入來源裡的位置，從 1 起算；j 是 c 在 B 的 schema 裡的位置），跟分析一樣不用欄位名稱當 key。

```json
{
  "map_1_0": {
    "type": "choice",
    "instructions": "來源「sales.csv」的欄位「order_date」，跟來源「民國年訂單.csv」的哪個欄位是同一種資料？",
    "criteria": {
      "f0": "欄位「訂單日期」",
      "f1": "欄位「出貨日」",
      "none": "都不是，這是另一種資料"
    }
  }
}
```

候選的 key 是 `f<i>`，i 是那個欄位在基準 schema 裡的位置。

### 3.4 送給 JEV 的 `state`

```json
{
  "sources": [
    { "name": "民國年訂單.csv", "rowCount": 6, "fields": [
      { "name": "訂單日期", "type": "date", "distinctCount": 6, "samples": ["2024-07-05", "2024-07-20", "2024-08-03"] },
      { "name": "出貨日", "type": "date", "distinctCount": 6, "samples": ["20240708", "20240722", "20240805"] },
      { "name": "地區", "type": "string", "distinctCount": 2, "samples": ["北區", "南區"] }
    ] },
    { "name": "sales.csv", "rowCount": 12, "fields": [ … ] }
  ]
}
```

- 只列參加這次合併的來源，照輸入的順序。
- 每個欄位的內容跟分析第一輪一樣：名稱、型別、相異值數量、樣本值（每筆照分析的規則截短）。敏感欄位只有名稱和型別，包括從輸入來源繼承來的敏感欄位。
- `rowCount` 用建立時記下的筆數；沒記的（V5 之前建立的外部 API、合併來源）不放這個鍵，不為了算筆數去載入資料。
- 不送資料列，也不送使用者在對應表上做過的調整。

### 3.5 怎麼採用答案

- 答案是 `none`、沒有回答、或 `confidence` 小於 0.5（跟分析共用 `ConfigAssembler.MIN_CONFIDENCE`）時，不採用。
- 同一個來源 B 有兩個以上的欄位選到基準的同一個欄位時，只採用 `confidence` 最高的那個；一樣高就取 B 的 schema 裡排前面的。其他的當作沒有對應。
- 不同的來源選到基準的同一個欄位是正常的，都採用，疊加本來就是這樣。

## 4. API

`POST /api/jev/mapping`

```json
{ "inputs": ["<基準 id>", "<來源 B id>"], "compare": false }
```

回傳：

```json
{ "matches": [ { "input": "<來源 B id>", "field": "order_date", "to": "訂單日期" } ] }
```

- `inputs` 要 2～5 個、不能重複、都是自己的來源。錯誤訊息沿用合併時的字句：不是 2～5 個回 400「疊加要選 2 到 5 個來源」，重複回 400「疊加的來源不能重複」，找不到或不是自己的來源回 404「找不到資料源」。
- 沒有任何要問的欄位時不呼叫 JEV，直接回空的 `matches`。
- JEV 失敗時照分析的規則：沒有設定 `TYPESAFE_API_KEY` 回 503，呼叫失敗回 502，訊息只帶狀態碼。
- 用分析的那個 `JevClient`（`analyzeJevClient`，使用者按了按鈕在等）。
- 不快取。同樣的來源再按一次，就再問一次。

## 5. 畫面

### 5.1 按鈕

合併分頁的方式是「疊加」或「對照」，而且選了 2 個以上的來源時，對應表上方出現「請 JEV 對欄位」按鈕（`mdi-auto-fix`）。等 JEV 回應時按鈕 `loading`，對應表可以照常操作。

### 5.2 套用

回應回來時，要是來源、方式已經換了，這份結果直接丟掉，跟預覽一樣。

每一筆 `{input, field, to}` 照下面的方式套到對應表：

1. 找到基準欄位 `to` 那一列：那一列的基準格子是 `to`，而且 `input` 那一格目前是「（無）」。
2. 找到 `field` 自己那一列，而且那一列還是照名稱自動對上的樣子：輸出名稱是 `field`，基準格子是「（無）」，`input` 那一格是 `field`，其他格子不是「（無）」就是 `field`。
3. 兩列都找得到，才把第 1 列的 `input` 格子設成 `field`，再把第 2 列的 `input` 格子清成「（無）」；第 2 列的格子都空了，就刪掉這一列。任何一列找不到，就表示使用者已經手動改過，這一筆跳過。

三個以上來源時，後面幾個來源的同名欄位會照名稱排在同一列，例如 sales 和北區的 `region`。JEV 對上的每一筆只搬自己那一格，那一列搬空了才刪。

使用者手動設好的對應不會被蓋掉，改過名稱的列也不動。套用之後定義變了，預覽照現有規則清掉，要重新預覽才能建立。

### 5.3 標示和提示

- JEV 填進去的格子，下拉選單下面加一個「JEV 建議」小標籤。使用者改了那一格，標籤就拿掉。
- 按鈕下方顯示一行：對上的時候寫「JEV 對上了 {n} 個欄位，建立前請先預覽確認」；一筆都沒有的時候寫「JEV 沒有找到可以對上的欄位」。
- 失敗時錯誤顯示在合併分頁現有的錯誤區，對應表不動。

## 7. 測試

後端：

- 題目：同名欄位不問；型別不同的欄位不會是候選；對照模式下數字欄位不問、不當候選；沒有候選的欄位不問；全部都不用問時不呼叫 JEV。
- `state`：敏感欄位（含繼承的）只有名稱和型別；沒記筆數的來源沒有 `rowCount`。
- 採用：`none`、信心低於 0.5 不採用；同一個來源兩個欄位搶同一個基準欄位時，留信心高的，一樣高時留排前面的；兩個來源對到同一個基準欄位時都留。
- API：`inputs` 少於 2 個、超過 5 個、重複、不是自己的來源都擋下。

前端：

- 按鈕只在疊加、對照而且有 2 個以上來源時出現。
- 套用：照 5.2 設好格子、刪掉多出來的列；使用者先手動改過的那一筆跳過；回應回來時來源已經換了就不套。
- 「JEV 建議」標籤在改了那一格之後消失；兩種提示文字。

瀏覽器（真的呼叫 JEV）：用 2026-09-30 示範的那一組，民國年訂單.csv 當基準、sales.csv 當第二個。期望結果是：`order_date`→訂單日期、`region`→地區、`amount`→金額三個對上；`product`、`qty`、`memo`、出貨日各自留成一列。JEV 對錯的地方照實記下來。題目改成英文的 backlog 項目（P2）要不要提前做，看這裡的結果決定。

## 8. 不做

- 查表的對接欄位建議（例如 `product` ↔ `code`），以及後端算對上比例的做法。
- 合併方式建議（疊加、對照還是查表）。
- 值的對齊（「北區」和「North」當成同一個值）。
- 從一句需求直接組出合併定義。

這幾項記進 backlog。

## 9. 決定

| 題目 | 選擇 | 沒選的 |
|---|---|---|
| JEV 先做哪一項 | 欄位對應建議（2026-09-30 已確認） | 對應＋查表對接；先只做刪除 |
| 什麼時候問 JEV | 按「請 JEV 對欄位」才問（2026-09-30 已確認） | 選好來源就自動問 |
| 三個以上來源 | 都跟第一個來源比，一次呼叫（2026-09-30 已確認） | 逐一累加比對，每多一個來源多一輪 |
| 後面幾個來源的同名欄位排在同一列時怎麼套用 | 只搬 JEV 對上的那一格，那一列搬空了才刪（2026-09-30 已確認，Task 3 審查後） | 那一列其他格子都要是「（無）」才套用，否則整筆跳過 |
| 「JEV 建議」標籤放在哪 | 下拉選單下面（2026-10-01，瀏覽器驗證後） | 下拉選單旁邊：三個以上來源時，欄位和標籤都被擠到看不到字 |
