# JEV 儀表板：比率（設計）

日期：2026-09-28
前提：對照來源見 `docs/superpowers/specs/2026-09-28-compare-datasource-design.md`（B2），合併來源見 `docs/superpowers/specs/2026-09-27-merged-datasource-design.md`（B1），每張圖各自一個來源見 `docs/superpowers/specs/2026-09-27-multi-source-dashboard-design.md`（A）。本文件只寫這次新增和改變的部分。

## 1. 目的

高階主管要看的常常不是金額，而是比率：退貨率、達成率、毛利率。

比率不能逐列算好再加總，每一列的退貨率加起來沒有意義。正確的算法是每一組先把分子、分母各自加總，再相除。例如 9 月的退貨率＝9 月退貨金額合計 ÷ 9 月銷售金額合計。

這次讓使用者在任何來源上定義「比率＝分子 ÷ 分母」。JEV 分析時把比率當成一個數值來挑圖，轉換器在分組加總之後再相除。

## 2. 範圍

做：

- 每個來源多一份比率清單，可以在欄位表新增、刪除。
- 轉換器：`value` 是比率時，每組分子、分母各自加總再相除。
- 折線圖、長條圖把比率顯示成百分比。
- JEV 分析把比率當成數值，只配時間或分類欄位。
- 比率圖的異常檢查改用百分點。
- 分子或分母是敏感欄位時，比率也算敏感。

不做：

- 編輯比率。要改就刪掉重加。
- 比率的圓餅、堆疊長條、熱力、雷達、散佈圖；「金額＋比率」組合圖；兩個數值的圖（B2 的 `measures`）放比率。
- 百分比以外的格式，例如人均營收。
- 分子、分母用筆數或平均；三個以上欄位的公式；比率的比率。
- 比率跟著合併傳給合併來源。
- 手動編圖。製圖頁的圖還是全由 JEV 挑。

## 3. 使用情境

| 情境 | 來源 | 比率 | 圖 |
|---|---|---|---|
| 每月退貨率 | 對照來源「銷售／退貨 對照」 | 退貨率＝`退貨·amount` ÷ `銷售·amount` | 折線圖：退貨只有 7～9 月，1～6 月留空 |
| 各區退貨率 | 同上 | 同上 | 長條圖：每區一根 |
| 各部門達成率 | 對照來源「預算／實際 對照」 | 達成率＝`實際·金額` ÷ `預算·金額` | 長條圖 |
| 每月毛利率 | 上傳的銷售明細（有 `revenue`、`gross_profit`） | 毛利率＝`gross_profit` ÷ `revenue` | 折線圖 |

前三個是對照來源，分子和分母來自不同的輸入來源；最後一個是一般來源，分子分母在同一份資料裡。兩種都要能用。

## 4. 資料模型

### 4.1 比率定義

```json
"ratios": [
  { "name": "退貨率", "numerator": "退貨·amount", "denominator": "銷售·amount" }
]
```

- 存在 `datasource.ratios_json`（Flyway V4：`jsonb not null default '[]'`）。上傳、外部 API、合併來源都有，舊來源不用搬資料。
- 清單的順序就是使用者加入的順序。
- `numerator`、`denominator` 寫的是欄位的原始名稱，不是顯示名稱。
- 比率不放進 `schema_json`。schema 是從實際欄位推斷出來的，明細表、敏感欄位繼承、送給 JEV 的樣本值都會逐欄讀 schema，混進比率就會出錯。
- 比率不會跟著合併傳下去。合併定義的輸出欄位只對應實際欄位，合併來源要用比率，就在合併來源上自己加。

### 4.2 驗證

每次更新都驗證整份清單：

- `name` 先去掉頭尾空白，不能是空的，最多 50 個字。
- `name` 不能跟這個來源任何欄位的名稱或顯示名稱重複，也不能跟清單裡其他比率重複。圖表的 dataset 用名稱當維度，重複了 ECharts 分不出來。
- `numerator`、`denominator` 都要是這個來源 schema 裡型別為 `number` 的欄位，而且不能是同一個欄位。

### 4.3 敏感

比率不存敏感設定，讀取來源時才算：分子或分母只要有一個敏感（包含從輸入來源繼承來的），這個比率就敏感，回傳時帶 `sensitive: true`。要取消，得先取消分子、分母的敏感設定。

## 5. 規則

### 5.1 計算

- 卡片的寫法不變：`{ x, value: "退貨率", aggregate: "sum", timeGrain }`，`value` 填比率名稱。
- `UniversalTransformer.transform` 多收這個來源的比率定義。`value` 是比率時：
  - 分組照舊：`x` 是空值的列跳過，有 `timeGrain` 就先分期。
  - 每組分子、分母各自加總，只看數字，不是數字的值跳過。
  - 比率＝分子加總 ÷ 分母加總。
  - 某一組完全沒有分子的值、完全沒有分母的值，或分母加總是 0，比率就是 `null`。這一組照樣輸出，x 軸上留著位置，折線斷開、長條留空。對照來源上 1～6 月沒有退貨資料，退貨率是空白，不是 0%。
  - 分子、分母都沒有任何值的組不輸出，跟 B2 兩個數值的圖一樣。
  - `aggregate` 不管寫 `sum`、`avg`、`count` 還是 `none`，都照上面的方式算。
- 排序跟單一數值的圖一樣：有 `timeGrain` 照期別排；沒有就照比率由大到小，`null` 排最後。
- `ChartData` 多一個 `percent: true`，只在數值欄是比率時出現，其他時候 JSON 不輸出。

### 5.2 比率能放的位置

- 比率只能放在 `value`。長條圖、折線圖用得到；圓餅、堆疊長條、熱力圖也走同一段分組，手動組的卡片照樣算得出來，但 JEV 不會挑這幾種圖。
- 放在 `x`、`y`、`series`、`measures`、`columns` 的比率名稱，當成找不到的欄位（`FIELD_MISSING`）。
- 分子或分母的欄位不在資料裡時，也是 `FIELD_MISSING`，`missingField` 寫那個欄位的名稱。
- 比率被刪掉之後，用到它的卡片是 `FIELD_MISSING`，`missingField` 是比率名稱。同名重加之後，卡片就恢復。

### 5.3 JEV 分析

- `state.fields` 在實際欄位後面接上每個比率：`{ "name": "退貨率", "type": "ratio", "formula": "退貨·amount ÷ 銷售·amount" }`。沒有樣本值和相異值數量。
- 第一輪：比率的題目接在欄位後面編號（有 n 個欄位時，第一個比率是 `imp_<n>`）。只問重要性，有需求時再問相關性（`rel_<n>`），不問角色，角色固定是 `measure`。
- 候選欄位：比率是使用者特地加的，不看重要性，一定進候選。排在角色不是 `ignore` 的焦點欄位後面、其他欄位前面，比率之間照重要性排；總數還是最多 8 個。
- 組合：比率配一個 `time` 欄位出折線、長條，配一個 `dimension` 欄位出長條。不出圓餅（比率不能相加）、散佈、雷達、堆疊長條、熱力圖，也不跟其他數值組成對照組。
- 對應：`{ x: 時間或分類, value: 比率名稱, aggregate: "sum", timeGrain: 照現有規則 }`。
- 排序：先比有沒有焦點欄位；再讓對照組合和比率組合排在其他組合前面，兩種同一層；最後比平均重要性。
- 對照來源上：分子、分母都有 `provides`（B2 spec 4.2）時，比率只看得到兩者 `provides` 的交集。組合裡的時間、分類欄位要在交集裡，不然不問（沿用 B2 的 `drawable`）。例如只有退貨有的 `reason`，不配退貨率。一般來源不受這條限制。
- 組合裡有比率時，題目（`describe`）多一句：「『退貨率』是比率＝退貨·amount ÷ 銷售·amount，每組先各自加總再相除。」
- 明細表不放比率，逐列算比率沒有意義。
- 調整模式照現有規則。

### 5.4 異常檢查

`HighlightSummarizer` 拿到 `percent` 的資料時：

- 每條系列的 `previous`、`current` 是百分比數字（5.0 代表 5%），變化寫 `changePoints`（`current − previous`，單位是百分點），不寫 `changePercent`。三個數字都四捨五入到小數一位。
- `metric` 寫比率名稱，另外加 `unit: "%"`。
- 最後一期或前一期的比率是 `null` 時，那條系列不比；一條可比的系列都沒有，這張圖就不做異常檢查。一般數值的「空值當 0」不適用於比率，因為沒有資料不代表比率是 0。
- 其他規則照舊：只比已經結束的期。
- 卡片用到敏感比率時整張跳過，跟用到敏感欄位一樣。`JevController.highlight` 的敏感清單要加上敏感的比率名稱。

### 5.5 標題和顯示名稱

- 自動標題沿用現有格式：「退貨率 依 date」。
- 比率名稱是使用者自己取的，沒有顯示名稱，套顯示名稱時不換；x 軸欄位照舊換，所以畫面上是「退貨率 依 日期」。

## 6. 畫面

### 6.1 欄位表的「比率」區

- 資料來源頁的欄位表下面多一區「比率 · N」，每一列是：
  - 名稱。
  - 公式：用分子、分母的顯示名稱，例如「退貨金額 ÷ 銷售金額」。
  - 敏感：敏感時標示出來，提示「分子或分母是敏感欄位」。
  - 刪除鈕（`aria-label` 是「刪除比率 退貨率」）。按下去直接刪，不另外確認。
- 一個比率都沒有時，寫：「比率＝分子 ÷ 分母，每一組先各自加總再相除，例如退貨率。」
- 「新增比率」開對話框：名稱、分子、分母。分子、分母的選單只列數字欄位，選項用顯示名稱。三個都填了、分子和分母不一樣，「新增」才能按。
- 新增、刪除都把整份清單送給後端；後端回 400 時，對話框或比率區顯示後端的訊息。

### 6.2 製圖頁

「欄位」標籤在實際欄位後面列出比率，圖示用百分比符號，滑過去顯示「退貨率（比率：退貨·amount ÷ 銷售·amount）」。勾了就當焦點欄位，跟一般欄位一樣。

### 6.3 圖表

- 長條圖、折線圖拿到 `percent` 時，Y 軸刻度和 tooltip 都用 `Intl.NumberFormat('zh-TW', { style: 'percent', maximumFractionDigits: 1 })`：0.052 顯示「5.2%」，0.05 顯示「5%」。
- `ChartCard` 的數字縮寫（`compactValueAxis`）不套在百分比的軸上。
- `null` 不畫：折線斷開，長條留空。

## 7. API

- `PATCH /api/datasources/{id}/ratios`：body 是 `{ "ratios": [ { "name", "numerator", "denominator" } ] }`，整份取代，回傳更新後的來源，寫法跟 `labels`、`sensitive` 一樣。新增、刪除都用這支。
- `GET /api/datasources` 每個來源都帶 `ratios`，沒有比率就是 `[]`，每個比率帶 4.3 算出來的 `sensitive`。
- 建立上傳、外部 API、合併來源時，`ratios` 一律是空的。
- 卡片的 `mapping` 格式不變，`value` 可以填比率名稱。

## 8. 錯誤處理

PATCH 驗證失敗一律回 400，訊息寫中文：

- 「比率名稱不能空白」
- 「比率名稱最多 50 個字」
- 「比率名稱『退貨率』跟欄位或其他比率重複」
- 「分子『amount』不是這個來源的數字欄位」（分母同樣寫法）
- 「分子和分母不能是同一個欄位」

來源不存在或不是自己的，照現有規則回 404。

## 10. 預設決定（2026-09-28 已確認）

| 項目 | 預設 | 另一種做法 |
|---|---|---|
| 誰定義比率 | 使用者在來源欄位表定義 | JEV 從對照組自動推 |
| 比率的圖型 | 折線、長條 | 再加熱力圖、「金額＋比率」組合圖 |
| 顯示格式 | 一律百分比，最多一位小數 | 每個比率自己選 |
| 異常檢查的變化 | 百分點 | 變化百分比；不做 |
| `aggregate` | 寫什麼都先加總再相除 | 只接受 `sum`，其他回 400 |
| 候選欄位 | 比率一定進候選 | 跟一般欄位一樣看重要性 |
| 比率組合排序 | 焦點之後，跟對照組合同一層 | 照重要性跟其他組合一起排 |
| 修改 | 只能新增、刪除 | 可以編輯 |
| 刪除 | 不另外確認 | 跳確認框 |
| 合併 | 不傳給合併來源 | 合併來源繼承輸入來源的比率 |
| 某組缺分子或分母 | 空白 | 補 0 |

## 11. 之後可以接的

- 「金額＋比率」組合圖：B2 的 `measures` 第二個是比率時，畫成折線走右軸。
- 百分比以外的格式：比率加一個格式設定，例如人均營收。
- 分子、分母用筆數：例如客單價＝營收 ÷ 訂單數。
- 比率的熱力圖：各區 × 各月的退貨率。轉換器已經算得出來，要補的是 JEV 組合和前端色階的百分比格式。
