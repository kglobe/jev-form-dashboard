結論

怎麼選
  • 要快、要常改、要精準控制動畫：選 python-pptx。這次寫好的動畫和轉場已經收進 ppt-master 的 pptx_fx.py，下次不用再寫。
  • 要放 SVG、要 slide zoom、不想碰 OOXML：選 OfficeCLI。做完一定要用 -Anim 檢查 presetID。
  • 動畫方向事後用 PowerPoint 存出的 XML 對照過。python-pptx 版的 wipe 原本整組反向，已經修正；OfficeCLI 版用 raw-set 修過的方向正確。

為什麼 OfficeCLI 比較貴

推測，沒有逐筆拆 token
  • 要學的比較多。officecli 的 skill 文件兩份約 9 萬字元，模型對 python-pptx 和 OOXML 本來就熟。
  • 每個操作都是一個 CLI 指令，工具呼叫多了七成。
  • 動畫 bug 要逐一查 XML、用 raw-set 修，驗收多跑一輪。
  • 跑一次 167 秒，python-pptx 只要 0.9 秒，每輪修改都要等。

OfficeCLI 1.0.153 的 bug

  • presetID 寫錯：wipe 寫成 20、zoom 21、split 15、float 12、自訂路徑 26。動畫窗格會顯示錯的名稱。
  • wipe 不管設哪個方向，filter 一律寫 wipe(left)。
  • float 實際是從投影片外飛進來的 Peek。
  • grow/shrink 固定放大 150%。
  • add animation 只接受 shape 和 chart。
  • link= 會寫到每個 run，字變藍加底線。
  • slide zoom 的縮圖是空白圖。
  • 8 碼色寫入是 AARRGGBB，glow 讀回卻是 RRGGBBAA。
  • 設了 morph 的頁，相鄰頁的 shape 名稱都會多出 !!，@name= 會找不到。
  • mermaid 原生轉換不吃 <br/>，8 個節點會擠成一排。
H

python-pptx 的痛點

  • 沒有動畫和轉場 API。時間樹、bldLst、grpId 的規則都要自己寫。
  • 線條透明度、文字效果、表格框線都沒有 API。
  • 自動形狀預設帶 p:style，每個都要拔掉，不然會吃到主題效果。
  • 不能放 SVG，也不能產生投影片縮圖。
  • 連接點只照外框算 4 個點，六角形要自己算。
